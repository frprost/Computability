Logic and computation: decidability, types and proofs

Where does the frontier between decidable and undecidable logics run? A single two-place relation is enough to draw the tape of a Turing machine. And, in the other direction, languages in which every program terminates are exactly proof systems: this is the Curry-Howard correspondence. From System F to the calculus of constructions, these languages are the core of the proof assistants Lean and Rocq, which today check proofs produced by humans and by AIs alike.

Some logics are simple enough for a machine always to decide whether a piece of reasoning is valid; others are not. And there is a surprising link between programs and proofs: a well-typed program is a proof.

This chapter explores two frontiers. The first separates the logics in which a machine can always say whether a statement is true in all cases from those in which this is impossible: it suffices to be able to speak of relations between two objects (“$x$ is the parent of $y$”) to tip over into the undecidable.

The second frontier concerns programming languages in which every program halts. They turn out to be exactly proof systems: writing a program of a certain type amounts to proving a statement. This correspondence, due to Haskell Curry and William Howard, is the basis of the software that checks mathematical proofs.

Computability was born of logic: Turing invented his machines to answer a question of logic, the decision problem. This chapter follows both directions of this link. In the first, we ask which logics can be decided: propositional calculus can, so can predicate calculus with one-place relations, but a single two-place relation is enough to tip everything over, because a binary relation can describe a grid, and hence the complete history of a computation (time on one axis, the tape on the other). In the second direction, we start from computation and arrive at logic: by forbidding programs that do not terminate, we obtain languages whose programs are, literally, proofs.

The frontier of the decidable in logic

With only “and”, “or”, “not” and “implies”, everything can be decided by trying all combinations of true and false. With properties of isolated objects (“$x$ is red”), everything can still be decided. As soon as one speaks of relations between two objects, the tape of a Turing machine can be described, and undecidability appears.

Theorem
Propositional calculus is decidable

One can decide whether a propositional formula (built from variables with $\neg,\wedge,\vee,\Rightarrow$) is a tautology. The problem is $\mathrm{co}\mathsf{NP}$-complete, and satisfiability is $\mathsf{NP}$-complete.

In plain words. Take a formula made of “and”, “or”, “not”, “implies” and a few elementary statements (“it is raining”, “I go out”). To know whether it is always true, it suffices to try all the ways of making these statements true or false.

With three elementary statements, there are 2 × 2 × 2 = 8 cases to try: this is the truth table learned in logic. The question is therefore always decidable. What remains difficult is time: with a hundred statements, there are more cases than atoms in the universe, and no much faster method is known (see Complexity). Undecidability begins only when logic starts speaking of objects, possibly infinitely many, and of relations between them.

A formula with $n$ variables has $2^n$ assignments; evaluate the formula on each (truth table), in time $O(2^n\cdot|\phi|)$. A formula is a tautology if and only if its negation is not satisfiable; satisfiability is $\mathsf{NP}$-complete (Cook and Levin), so the tautologies form a $\mathrm{co}\mathsf{NP}$-complete problem (passing to the complement, with the reduction $\phi\mapsto\neg\phi$).

Theorem
Monadic logic is decidable (Löwenheim, 1915)

Consider the sentences of predicate calculus without equality whose only symbols are unary relations $P_1,\dots,P_k$ (no function, no constant, no two-place relation). If such a sentence has a model, it has a model with at most $2^k$ elements. Consequently, validity of these sentences is decidable.

In plain words. A logic that speaks only of properties of isolated objects (“being red”, “being mortal”), without ever relating two objects to each other, is decidable.

With such properties, one can only sort objects into boxes: red or not, mortal or not, and so on. Two objects in the same box cannot be told apart with this language, and the number of boxes is finite. One cannot say “this one is next to that one”, nor “this one comes after that one”: one therefore cannot describe a computation, which moves from one step to the next. This is the logic of Aristotle’s syllogisms (“all men are mortal, Socrates is a man, so Socrates is mortal”), and that is why one can always decide.

Let $\mathcal M$ be a model with domain $D$. The type of an element $a$ is $\tau(a)=(\chi_{P_1}(a),\dots,\chi_{P_k}(a))\in\{0,1\}^k$. Let $\mathcal M'$ be the structure whose domain is the set $D'=\tau(D)$ of realized types (at most $2^k$ elements, and at least one, since $D\ne\emptyset$), where $P_i$ is true of a type $t$ if and only if $t_i=1$.

Lemma. For every formula $\phi(x_1,\dots,x_n)$ and all $a_1,\dots,a_n\in D$: $\mathcal M\models\phi(\vec a)\iff\mathcal M'\models\phi(\tau(a_1),\dots,\tau(a_n))$. By induction on $\phi$. For an atom $P_i(x_j)$, this is the definition of $\mathcal M'$. The connectives go through without difficulty. For $\exists y\,\phi$: $\mathcal M\models\exists y\,\phi(y,\vec a)$ if and only if there is $b\in D$ with $\mathcal M\models\phi(b,\vec a)$, if and only if (induction hypothesis) there is $b$ with $\mathcal M'\models\phi(\tau(b),\tau(\vec a))$, if and only if there is $t\in D'$ with $\mathcal M'\models\phi(t,\tau(\vec a))$, since $D'$ is exactly the set of the $\tau(b)$. The case $\forall$ follows by $\forall=\neg\exists\neg$.

Applied to a sentence, the lemma gives the announced model. To decide whether $\phi$ is valid, check whether $\neg\phi$ has a model: it suffices to try the structures with domain $\{1,\dots,m\}$ for $m\le2^k$, finitely many ($2^{km}$ interpretations for each $m$), and to evaluate $\neg\phi$ in each, which is a finite computation on a finite domain.

The program logique.py applies this procedure. It confirms that the syllogism above is valid, and it finds a two-element countermodel for the false sentence “if there is a $P$ and a $Q$, there is an object that is both $P$ and $Q$”. The procedure is doubly exponential; one does much better in practice, but the problem remains at least as hard as SAT, which is a special case of it.

Theorem
One binary relation suffices to make logic undecidable

Validity of sentences of predicate calculus is undecidable as soon as the language contains two-place relations. More precisely, the Church-Turing theorem associates with every machine $Z$ and every input $x$ a sentence, valid if and only if $Z$ halts on $x$, which uses only binary relations, one constant and two unary functions. Result quoted for information: a single binary relation, with no other symbol, already suffices (Kalmár, 1936).

In plain words. As soon as a logic can speak of a relation between two objects (“is next to”, “comes after”), no machine can decide in general whether a statement is always true. A single relation of this kind suffices to describe the working of a Turing machine.

The frontier is sharp: isolated properties, everything is decidable; one two-place relation, nothing is any more. The reason can be pictured. The computation of a Turing machine is a big table: one row per instant, one column per tape cell. A relation between two objects suffices to locate a cell of the table by its row and its column. A few rules that look only at neighbouring cells suffice to say “each row follows from the previous one according to the program”. Deciding whether a statement is always true would amount to deciding whether this table has a last row, that is, whether the machine halts.

The same idea recurs throughout this manual: tilings of the plane, Post’s dominoes, equations in integers. Whenever a language can describe a grid in which each cell depends on its neighbours, it can imitate a computation, and it inherits its undecidability.

The reduction of the Church-Turing theorem uses exactly this coding: the binary relations $Q_i(t,h)$ (“at instant $t$, state $q_i$, head at $h$”) and $C_j(t,u)$ (“at instant $t$, cell $u$ contains $S_j$”), plus $E$ and $L$ for equality and the order of cells, a constant $o$ and the functions $s,p$ (successor, predecessor). The function symbols are not indispensable: they can be replaced by their graphs, binary relations, adding axioms saying that these relations are functional and total; this is a classical transformation, not detailed here. A shorter reduction, which goes through Post’s problem and uses only one binary relation, one binary function and constants, is proved in full just after.

Comparison with the monadic case: the reduction needs to speak of pairs (instant, cell), which unary predicates do not allow. It is also known (results quoted) that monadic logic remains decidable with equality, and that classes of sentences defined by the shape of their quantifier prefix are decidable (prefix $\exists^\ast\forall^\ast$, Bernays and Schönfinkel, 1928) or undecidable (prefix $\forall\exists\forall$, Kahr, Moore and Wang, 1962).

Theorem
From Post’s problem to logic: one binary relation and one binary function suffice (Floyd)

Let $\mathcal D=\big(\frac{u_1}{v_1},\dots,\frac{u_k}{v_k}\big)$ be a list of dominoes over an alphabet $\Lambda$. The language $\mathcal L$ has a constant $e$, a constant $\underline a$ for each letter $a\in\Lambda$, a binary function symbol $c$ and a binary relation symbol $P$. For a term $x$ and a word $w=a_1\cdots a_n$, write $x\cdot w$ for the term $c(\cdots c(c(x,\underline{a_1}),\underline{a_2})\cdots,\underline{a_n})$. Let

$$\varphi_{\mathcal D}\;=\;\Big[\bigwedge_{i=1}^kP(e\cdot u_i,\,e\cdot v_i)\ \wedge\ \forall x\,\forall y\,\Big(P(x,y)\Rightarrow\bigwedge_{i=1}^kP(x\cdot u_i,\,y\cdot v_i)\Big)\Big]\ \Rightarrow\ \exists z\,P(z,z).$$

Then $\varphi_{\mathcal D}$ is valid if and only if $\mathcal D$ has a solution. Consequently, validity of sentences of $\mathcal L$ is not decidable, and, composing with the reduction from machines to dominoes, one obtains for every machine $Z$ and every input $\vec x$ a sentence of $\mathcal L$ that is valid if and only if $Z$ halts on $\vec x$.

In plain words. Post’s game of dominoes translates into a logical sentence that uses only one relation between two objects and one operation on two objects. The sentence is always true exactly when the game has a solution. Since one cannot decide whether a game of dominoes has a solution, one cannot decide either whether such a sentence is always true.

The sentence says, in substance: “if each domino is a possible pair, and if a possible pair can always be extended by a domino, then there is a possible pair whose two sides are equal”. The two-place operation is “add a letter at the end of a word”; the two-place relation is “these two words can be the top and bottom of a sequence of dominoes”. The sentence is always true when the game has a solution, since the solution can then be written out. If the game has no solution, there is a world in which the sentence is false: the world of words themselves.

We meet again the frontier already encountered: with properties of isolated objects, everything is decidable; as soon as two objects can be related, a computation can be written. Dominoes, two-stack machines and two-counter machines are three ways of seeing the same phenomenon: two linked memories suffice to compute everything, and a two-place relation suffices to describe everything.

The term $e\cdot w$ depends only on the word $w$, and $(x\cdot w)\cdot w'=x\cdot ww'$ (it is the same term, by definition).

If $\mathcal D$ has a solution, $\varphi_{\mathcal D}$ is valid. Let $\mathcal M$ be a structure satisfying the hypotheses of $\varphi_{\mathcal D}$. By induction on $m\ge1$, for every sequence $i_1,\dots,i_m$, $\mathcal M$ satisfies $P(e\cdot u_{i_1}\cdots u_{i_m},\ e\cdot v_{i_1}\cdots v_{i_m})$: for $m=1$ this is one of the first hypotheses; to go from $m$ to $m+1$, apply the second hypothesis with $x=e\cdot u_{i_1}\cdots u_{i_m}$, $y=e\cdot v_{i_1}\cdots v_{i_m}$. If $i_1,\dots,i_m$ is a solution, the two words are equal, so the two terms are the same term $t$, and $\mathcal M$ satisfies $P(t,t)$, hence $\exists z\,P(z,z)$. Thus $\varphi_{\mathcal D}$ is true in every structure.

If $\varphi_{\mathcal D}$ is valid, $\mathcal D$ has a solution. Consider the structure of words $\mathcal M_{\mathcal D}$: its domain is the set $\Lambda^*$ of words, $e$ is the empty word, $\underline a$ is the one-letter word $a$, $c(x,y)$ is the concatenation $xy$, and $P(x,y)$ is true if and only if there are $m\ge1$ and $i_1,\dots,i_m$ with $x=u_{i_1}\cdots u_{i_m}$ and $y=v_{i_1}\cdots v_{i_m}$. In $\mathcal M_{\mathcal D}$, the term $x\cdot w$ is interpreted as the word $xw$; the hypotheses of $\varphi_{\mathcal D}$ are true there (a sequence of one domino, then the extension of a sequence by a domino), and the conclusion $\exists z\,P(z,z)$ is true there if and only if $\mathcal D$ has a solution. If $\varphi_{\mathcal D}$ is valid, it is true in $\mathcal M_{\mathcal D}$, and $\mathcal D$ has a solution.

Consequences. $\mathcal D\mapsto\varphi_{\mathcal D}$ is computable; since Post’s problem is undecidable, so is validity in $\mathcal L$, and it is $\Sigma_1$-complete since it is semi-decidable (completeness). The constants are not indispensable: $\underline a$ and $e$ can be replaced by variables universally quantified at the head of the sentence, since the proof uses only the fact that the terms $e\cdot w$ and $e\cdot w'$ are equal when $w=w'$. One can also replace the function $c$ by unary functions $f_a(x)=c(x,\underline a)$, one per letter: this is the original form of the reduction (Floyd, published in Manna’s textbook, 1974). Results quoted for information: a single binary relation, with no other symbol, suffices for undecidability (Kalmár, 1936); on the other hand, the logic whose only symbol is a unary function is decidable (Ehrenfeucht, 1959), and two unary functions, or one binary function, are needed to recover undecidability.

For the dominoes $\frac{a}{baa},\frac{ab}{aa},\frac{bba}{bb}$ (letters $a=\ell_0$, $b=\ell_1$), the program writes the sentence and, from the solution $3,2,3,1$, the chain of facts that proves it:

Technological workshop — Floyd’s sentence, in Python

The file post_logic.py writes the sentence $\varphi_{\mathcal D}$ (with the binary function $c$, or with unary functions), the deduction of $P(t,t)$ from a solution, and explores the model of words.

def term(x, word, binary, names):
    """The term x.word, written with unary functions f_a or with the binary function c."""
    t = x
    for a in word:
        t = "c(%s,%s)" % (t, names[a]) if binary else "f_%s(%s)" % (names[a], t)
    return t


def letter_names(dominoes):
    letters = sorted({a for h, b in dominoes for a in h + b})
    return {a: "l%d" % k for k, a in enumerate(letters)}


def sentence(dominoes, binary=True, tptp=False):
    """Floyd's sentence, in readable notation or in TPTP format (fof)."""
    names = letter_names(dominoes)
    if tptp:
        X, Y, Z, E = "X", "Y", "Z", "e"
        base = " & ".join("p(%s,%s)" % (term(E, h, binary, names), term(E, b, binary, names)) for h, b in dominoes)
        step = " & ".join("p(%s,%s)" % (term(X, h, binary, names), term(Y, b, binary, names)) for h, b in dominoes)
        return "fof(post, conjecture, ( ( (%s) & ! [X,Y] : ( p(X,Y) => (%s) ) ) => ? [Z] : p(Z,Z) ) )." % (base, step)
    base = " ∧ ".join("P(%s, %s)" % (term("e", h, binary, names), term("e", b, binary, names)) for h, b in dominoes)
    step = " ∧ ".join("P(%s, %s)" % (term("x", h, binary, names), term("y", b, binary, names)) for h, b in dominoes)
    return "[ %s ∧ ∀x ∀y ( P(x, y) → %s ) ] → ∃z P(z, z)" % (base, step)


def deduction(dominoes, solution, binary=True):
    """If the sequence of indices is a solution, the list of facts P(s, t) deduced from the hypotheses,
    one domino after another; the last one has the form P(t, t), which proves the conclusion."""
    names = letter_names(dominoes)
    h, b = dominoes[solution[0]]
    facts = [(term("e", h, binary, names), term("e", b, binary, names))]
    for i in solution[1:]:
        u, v = dominoes[i]
        x, y = facts[-1]
        facts.append((term(x, u, binary, names), term(y, v, binary, names)))
    return facts

Chained with post.py, it gives, for the successor machine on input $0$, a sentence of 1,442 characters, valid since the machine halts, and a deduction of 11 stages: python3 post_logic.py --machine examples/successor.tm 0.

"""post_logic.py: from the Post problem to first-order logic (Floyd's reduction).

To a list of dominoes (u_1/v_1, ..., u_k/v_k) we associate the sentence

    phi = [ AND_i P(u_i, v_i)  and  for all x, y : P(x, y) -> AND_i P(x.u_i, y.v_i) ]  ->  there is z : P(z, z)

where P is a binary relation symbol, e a constant (the empty word), and "x.w" the term obtained by
appending to x the letters of w one by one. Two ways of writing this term:
  * with one unary function f_a per letter a: x.ab = f_b(f_a(x));
  * with ONE single binary function c (append a letter) and one constant per letter: x.ab = c(c(x, a), b).
The second uses only symbols of arity at most two: a binary relation, a binary function,
constants. phi is valid (true in every structure) if and only if the dominoes have a solution.

With post.py, we obtain, for every Turing machine Z and every input x, a sentence that is valid if and
only if Z halts on x: validity is therefore not decidable (theorem of Church and Turing).

    python3 post_logic.py                   # the example a/baa, ab/aa, bba/bb: sentence and deduction
    python3 post_logic.py --tptp            # the sentence in TPTP format, for a prover (E, Vampire)
    python3 post_logic.py --machine examples/successor.tm 0

MIT licence. Authors: Frédéric Prost and Claude.
"""
import sys

import post


def term(x, word, binary, names):
    """The term x.word, written with unary functions f_a or with the binary function c."""
    t = x
    for a in word:
        t = "c(%s,%s)" % (t, names[a]) if binary else "f_%s(%s)" % (names[a], t)
    return t


def letter_names(dominoes):
    letters = sorted({a for h, b in dominoes for a in h + b})
    return {a: "l%d" % k for k, a in enumerate(letters)}


def sentence(dominoes, binary=True, tptp=False):
    """Floyd's sentence, in readable notation or in TPTP format (fof)."""
    names = letter_names(dominoes)
    if tptp:
        X, Y, Z, E = "X", "Y", "Z", "e"
        base = " & ".join("p(%s,%s)" % (term(E, h, binary, names), term(E, b, binary, names)) for h, b in dominoes)
        step = " & ".join("p(%s,%s)" % (term(X, h, binary, names), term(Y, b, binary, names)) for h, b in dominoes)
        return "fof(post, conjecture, ( ( (%s) & ! [X,Y] : ( p(X,Y) => (%s) ) ) => ? [Z] : p(Z,Z) ) )." % (base, step)
    base = " ∧ ".join("P(%s, %s)" % (term("e", h, binary, names), term("e", b, binary, names)) for h, b in dominoes)
    step = " ∧ ".join("P(%s, %s)" % (term("x", h, binary, names), term("y", b, binary, names)) for h, b in dominoes)
    return "[ %s ∧ ∀x ∀y ( P(x, y) → %s ) ] → ∃z P(z, z)" % (base, step)


def deduction(dominoes, solution, binary=True):
    """If the sequence of indices is a solution, the list of facts P(s, t) deduced from the hypotheses,
    one domino after another; the last one has the form P(t, t), which proves the conclusion."""
    names = letter_names(dominoes)
    h, b = dominoes[solution[0]]
    facts = [(term("e", h, binary, names), term("e", b, binary, names))]
    for i in solution[1:]:
        u, v = dominoes[i]
        x, y = facts[-1]
        facts.append((term(x, u, binary, names), term(y, v, binary, names)))
    return facts


def model_of_words(dominoes, depth):
    """The "natural" model: the objects are the words, e is the empty word, x.w is concatenation,
    and P(x, y) is true if (x, y) is obtained by chaining dominoes. The hypotheses of phi are true there,
    and the conclusion is true there if and only if the dominoes have a solution. We enumerate the pairs
    obtained with at most "depth" dominoes and look for a pair (z, z)."""
    pairs = {d: [i] for i, d in enumerate(dominoes)}
    front = dict(pairs)
    for _ in range(depth):
        for (x, y), s in front.items():
            if x == y:
                return s
        new = {}
        for (x, y), s in front.items():
            for i, (u, v) in enumerate(dominoes):
                c = (x + u, y + v)
                n = min(len(c[0]), len(c[1]))
                if c[0][:n] == c[1][:n] and c not in pairs:
                    pairs[c] = s + [i]
                    new[c] = s + [i]
        front = new
    for (x, y), s in front.items():
        if x == y:
            return s
    return None


def _main(argv):
    if "--machine" in argv:
        from machines import Machine
        k = argv.index("--machine")
        machine = Machine.from_file(argv[k + 1])
        args = [int(a) for a in argv[k + 2:] if not a.startswith("--")]
        dm, names = post.modified_dominoes(machine, *args)
        dominoes = post.to_ordinary(dm)
        sol = post.ordinary_solution(post.solution_from_computation(machine, dm, names, *args), len(dm))
        e = sentence(dominoes, tptp="--tptp" in argv)
        print("Machine of %d quadruples -> %d dominoes -> sentence of %d characters." % (len(machine), len(dominoes), len(e)))
        if "--tptp" in argv:
            print(e)
        f = deduction(dominoes, sol)
        assert f[-1][0] == f[-1][1]
        print("The machine halts: the deduction has %d stages and ends with P(t, t), with t of %d characters."
              % (len(f), len(f[-1][0])))
        return
    dominoes = [(("a",), ("b", "a", "a")), (("a", "b"), ("a", "a")), (("b", "b", "a"), ("b", "b"))]
    if "--tptp" in argv:
        print(sentence(dominoes, tptp=True))
        return
    print("Dominoes: a/baa, ab/aa, bba/bb (letters a = l0, b = l1)")
    print("Sentence, with a binary function c:")
    print("  " + sentence(dominoes))
    print("The same, with unary functions:")
    print("  " + sentence(dominoes, binary=False))
    sol = model_of_words(dominoes, 8)
    print("Solution found in the model of words:", [i + 1 for i in sol])
    for x, y in deduction(dominoes, sol):
        print("  P(%s, %s)" % (x, y))
    print("The last fact is P(t, t): the sentence is proved.")


if __name__ == "__main__":
    _main(sys.argv)
Remark
Validity, finite validity, decidable theories

Results quoted for information, except the first point.

  • The valid first-order sentences form a semi-decidable set (completeness), not decidable: they are $\Sigma_1$-complete.
  • The sentences true in all finite structures do not even form a semi-decidable set (Trakhtenbrot, 1950): by restricting to the finite, one loses the completeness theorem.
  • Some theories are decidable: the arithmetic of addition alone (Presburger, 1929), the theory of the real numbers with addition and multiplication (Tarski, 1948), elementary geometry. Adding multiplication to the integers tips everything over (incompleteness): with $+$ and $\times$ on $\N$, one can speak of finite sequences, hence of computations. The next chapter is devoted to these decidable theories.

In plain words. We know how to recognize the logical sentences that are always true: we look for their proof, and if it exists we find it. We do not know how to recognize those that are not. As for particular mathematical theories, some are decidable and others are not, depending on what they allow one to say.

This is exactly the semi-decidable situation of the previous chapter: the “yes” can be observed (here is the proof), the “no” cannot. Surprisingly, if one restricts oneself to finite worlds, it is worse: the sentences true in all finite worlds can no longer even be listed by a program. Infinity, here, simplifies things. The theories we know how to decide, such as elementary geometry or arithmetic without multiplication, are presented in the chapter Decidable theories.

Languages in which every program terminates

One can design languages in which each program receives a “type” that guarantees it halts. These languages are safe, but, as the chapter Motivations announced, they cannot compute everything.

The halting problem says that programs that terminate cannot be sorted out automatically. But one can design a language all of whose programs terminate, by restricting what one is allowed to write: the primitive recursive functions are an example. The question is what is lost. The answer, always the same, comes from the diagonal: a total language cannot contain its own interpreter.

Definition
Simply typed λ-calculus

Types are built from atomic types $o,p,q,\dots$ with the arrow: $A,B::=o\mid p\mid\cdots\mid A\to B$ (the arrow associates to the right). A context $\Gamma$ is a list $x_1:A_1,\dots,x_n:A_n$ of typed variables. The judgment $\Gamma\vdash M:A$ (“in context $\Gamma$, the term $M$ has type $A$”) is defined by three rules:

$$\frac{}{\Gamma,x:A\vdash x:A}\qquad\frac{\Gamma,x:A\vdash M:B}{\Gamma\vdash\lambda x.M:A\to B}\qquad\frac{\Gamma\vdash M:A\to B\quad\Gamma\vdash N:A}{\Gamma\vdash M\,N:B}$$

A term is typable if it has a type in some context.

In plain words. Each function of the λ-calculus is given a label, its type, such as “function that takes a number and returns a number”. Any expression in which the labels do not match is then rejected, just as one refuses to add metres and kilograms.

A type is a promise: “give me a number, I will give you back a number”. A function that applies itself to itself can keep no promise of this kind: it would have to be both the thing transformed and the tool that transforms. Types therefore forbid self-application, and with it the term that copies itself forever, met in the chapter λ-calculus.

$\lambda x.\,x\,x$ is not typable: the application rule would force the type $A$ of $x$ to be of the form $A\to B$, impossible since a type is a finite tree, strictly larger than its subtypes. On the other hand, $\lambda x.x:A\to A$ for every $A$, $\mathsf K=\lambda x.\lambda y.\,x:A\to B\to A$, and the Church numerals $\mathbf n=\lambda f.\lambda x.\,f^n\,x$ all have type $(o\to o)\to o\to o$. Typing is preserved by β-reduction (subject reduction): if $\Gamma\vdash M:A$ and $M\to_\beta M'$, then $\Gamma\vdash M':A$. This is proved by a substitution lemma: if $\Gamma,x:A\vdash M:B$ and $\Gamma\vdash N:A$, then $\Gamma\vdash M[x:=N]:B$ (induction on $M$).

Theorem
Normalization of simply typed λ-calculus (Turing, Tait)

Every typable term has a normal form. (Better, a result of Tait, 1967, quoted here for information: every sequence of β-reductions starting from a typable term is finite.)

In plain words. In the typed λ-calculus, every computation halts. Types prevent functions from applying themselves to themselves, which removes infinite loops.

A trade has been made. We cannot decide whether an arbitrary program halts. But we can decide whether a program is well typed (a simple algorithm checks the labels), and being well typed guarantees halting. An impossible question has been replaced by an easy check, at the price of a restriction: some programs, though harmless, are rejected.

Define the height of a type: $h(o)=0$, $h(A\to B)=1+\max(h(A),h(B))$. The degree of a redex $(\lambda x.M)\,N$, where $\lambda x.M:A\to B$, is $h(A\to B)$. To a term associate the pair $(d,n)$ formed by the maximal degree $d$ of its redexes and the number $n$ of redexes of that degree (and $(0,0)$ if it is normal). Order these pairs lexicographically; this is a well-order.

Let $R=(\lambda x.M)\,N$ be a redex of maximal degree $d$ containing no other redex of degree $d$ (take one minimal for inclusion). Contract it to $M[x:=N]$. The redexes of degree $d$ outside $R$ are neither duplicated nor changed in degree. The copies of $N$ contain only redexes of degree $<d$. There remain the redexes created by the contraction, of three kinds: (1) if $M$ is an abstraction $\lambda y.P$ and $R$ was applied to a term $Q$, the new redex $(\lambda y.P[x:=N])\,Q$ has as degree the height of the type $B$ of $M$; (2) if $M=x$ and $R$ was applied to $Q$, the new redex $N\,Q$ has degree $h(A)$; (3) if $M$ contains an application $x\,P$ and $N$ is an abstraction, the new redex $N\,P[x:=N]$ has degree $h(A)$. In all cases the degree is $<h(A\to B)=d$. Thus the number of redexes of degree $d$ decreases by 1, without creating others of degree $\ge d$: the pair $(d,n)$ strictly decreases. A strictly decreasing sequence for a well-order is finite: this strategy reaches a normal form. The argument is due to Turing (manuscript from the 1940s, published by Gandy in 1980).

Definition
Gödel’s System T (1958)

Add to the simple types a type $\mathbf N$ of integers, and to the terms the constants $0:\mathbf N$, $\mathsf S:\mathbf N\to\mathbf N$, and for each type $A$ a recursor $\mathsf R_A:A\to(\mathbf N\to A\to A)\to\mathbf N\to A$, with the computation rules

$$\mathsf R\,a\,g\,0\to a,\qquad \mathsf R\,a\,g\,(\mathsf S\,n)\to g\,n\,(\mathsf R\,a\,g\,n).$$

Results quoted for information: every term of System T normalizes (Tait, 1967), and the functions $\N\to\N$ definable in T are exactly the recursive functions whose totality is provable in Peano arithmetic (Gödel, 1958; Kreisel).

In plain words. Gödel added to the typed λ-calculus the integers and reasoning by induction. In this language, System T, every program still halts, and yet it computes much more than ordinary “repeat n times” loops, for example the Ackermann function.

The secret is to allow recursion not only on numbers, but on functions: one can define, step by step, a function that builds a function that builds a function… This simple addition brings enormous power (see Ackermann). The language remains safe, but like every language in which everything halts, it does not compute everything.

Ackermann in T. Set $\mathsf{it}=\lambda n.\lambda f.\lambda a.\ \mathsf R_{\mathbf N}\,a\,(\lambda k.f)\,n$, which computes $f^n(a)$. For Péter’s function, we have $A(m+1,n)=A(m,\cdot)^{\,n+1}(1)$: indeed $A(m+1,0)=A(m,1)$, and $A(m+1,n+1)=A(m,A(m+1,n))$. So define, by a recursion at type $\mathbf N\to\mathbf N$:

$$\mathsf{ack}=\lambda m.\ \mathsf R_{\mathbf N\to\mathbf N}\ \mathsf S\ \big(\lambda k.\lambda f.\lambda n.\ \mathsf{it}\,(\mathsf S\,n)\,f\,(\mathsf S\,0)\big)\ m,$$

so that $\mathsf{ack}\,0=\mathsf S$ and $\mathsf{ack}\,(m+1)=\lambda n.\,(\mathsf{ack}\,m)^{n+1}(1)$. By induction on $m$, $\mathsf{ack}\,m\,n$ reduces to $A(m,n)$.

The program logique.py translates this term literally into Python (the recursor becomes a loop) and checks that it agrees with Péter’s definition for $m<4$, $n<5$; for example $\mathsf{ack}\,3\,3=61$. The proof assistants Coq (Rocq), Lean and Agda rest on total languages of this kind, much richer; they reject a recursive definition if they cannot check that it terminates.

Theorem
A total language does not contain its interpreter

Let $\mathcal L$ be a language of programs, each defining a total function $\N\to\N$, with a coding $p\mapsto\ulcorner p\urcorner$ of programs by integers, and such that the functions definable in $\mathcal L$ are closed under composition with the successor and under diagonalization ($n\mapsto f(n,n)$). Then the evaluation function $(\ulcorner p\urcorner,n)\mapsto p(n)$ is not definable in $\mathcal L$. This is the case for the primitive recursive functions, simply typed λ-calculus, System T, and all the total languages of the next section (System F, calculus of constructions).

In plain words. A language in which every program halts cannot contain a program able to run all its programs, what is called an interpreter.

This is Cantor’s diagonal once more. If the interpreter existed in the language, one could write the program “run program number n on n, and add 1”; this program would be in the list and yet would differ from each one. A universal language such as Python contains its own interpreter, but one cannot know whether its programs halt. A safe language guarantees halting, but it lacks at least one function: its own. It can be added; one obtains a stronger language, still safe, which lacks its new interpreter, and so on, without ever reaching all computable functions.

If $E$ defined evaluation, $d(n)=E(n,n)+1$ would be definable, so $d$ would be computed by a program $p$. Then $d(\ulcorner p\urcorner)=p(\ulcorner p\urcorner)=E(\ulcorner p\urcorner,\ulcorner p\urcorner)$, and also $d(\ulcorner p\urcorner)=E(\ulcorner p\urcorner,\ulcorner p\urcorner)+1$: contradiction. This is the argument of the theorem on total functions, applied inside a language. For the primitive recursive functions, see also the corresponding exercise.

The Curry-Howard correspondence

A type such as “function that transforms an A into a B” can be read “if A, then B”. A program of this type is then a proof of the implication: it transforms every proof of A into a proof of B. Programming and proving become the same activity.

Theorem
Types are statements, programs are proofs

Read the type $A\to B$ as the implication “$A$ implies $B$”, and the atomic types $o,p,q,\dots$ as atomic propositions. Then a type $A$ is the type of a closed term if and only if $A$ is provable in minimal implicational logic, that is, in natural deduction with only the rules

$$\frac{}{\Gamma,A\vdash A}\ (\text{hyp})\qquad\frac{\Gamma,A\vdash B}{\Gamma\vdash A\Rightarrow B}\ ({\Rightarrow}\text{I})\qquad\frac{\Gamma\vdash A\Rightarrow B\quad\Gamma\vdash A}{\Gamma\vdash B}\ ({\Rightarrow}\text{E}).$$

Moreover, β-reduction of a term corresponds to the elimination of detours in the corresponding proof.

In plain words. A type can be read as a logical statement, and a program of this type as a proof of this statement. Running the program amounts to simplifying the proof.

Take “if A, then B”. Proving it is providing a method that transforms every proof of A into a proof of B: it is a function. Using this implication with a proof of A is applying the function. The rules of reasoning and the rules of programming are the same, apart from the names:

This correspondence, noticed by Curry (1934) then by Howard (1969), is at the heart of the software that checks proofs: checking a proof is checking the type of a program, which a machine can always do, whereas finding a proof cannot be done in general.

From terms to proofs. By induction on a derivation of $\Gamma\vdash M:A$, erase the terms: the variable rule becomes (hyp), abstraction becomes (${\Rightarrow}$I), application (${\Rightarrow}$E). One gets a proof of $A$ under the hypotheses of $\Gamma$; if $M$ is closed, with no hypothesis. From proofs to terms. Conversely, annotate a proof by giving a variable name to each hypothesis; each rule builds the corresponding term. Examples: $\lambda x.\lambda y.\,x:A\to B\to A$ proves $A\Rightarrow(B\Rightarrow A)$; $\lambda x.\lambda y.\lambda z.\,x\,z\,(y\,z):(A\to B\to C)\to(A\to B)\to A\to C$ proves the second axiom of Hilbert systems. These are the combinators $\mathsf K$ and $\mathsf S$ (this $\mathsf S$ of combinatory logic has nothing to do with the successor $\mathsf S$ of System T), and modus ponens is application: Hilbert-style logic is combinatory logic.

Detours and reduction. A detour is an introduction (${\Rightarrow}$I) immediately followed by an elimination (${\Rightarrow}$E) of the same implication: one proves $A\Rightarrow B$ only to apply it at once to a proof of $A$. This is exactly a redex $(\lambda x.M)\,N$, and eliminating it (replacing each use of hypothesis $A$ by the proof of $A$) is exactly $M[x:=N]$.

Corollary
Normalization implies consistency

No closed term has an atomic type, such as $o$. In other words, minimal implicational logic does not prove an atomic proposition without hypotheses: it is consistent. More generally, a provable formula has a proof without detours.

In plain words. Since every computation halts in the typed λ-calculus, a false statement cannot be proved in it. The halting of programs guarantees that the logic does not contradict itself.

The reasoning is as follows: every proof, seen as a program, simplifies to a form without detours, and one checks by hand that no proof without detours proves an elementary statement from nothing. In 1936, Gentzen used an idea of this kind to prove that arithmetic does not contradict itself. To do so, he had to use a reasoning stronger than arithmetic itself; this is unavoidable, by the second incompleteness theorem.

A normal term can be written $\lambda x_1\cdots\lambda x_n.\,y\,M_1\cdots M_k$, where $y$ is a variable (by induction on the term: a normal term that is not an abstraction is a variable applied to arguments, otherwise it would contain a redex). Suppose $\vdash M:o$ with $M$ closed. By normalization and subject reduction, $M$ has a closed normal form $M'$ of type $o$. Since $o$ is not an arrow, $n=0$, and $M'=y\,M_1\cdots M_k$ with $y$ free: contradiction with $M'$ being closed. For the second claim, the normal form of a term is a detour-free proof of the same statement.

Results quoted for information: Peirce’s law $((A\Rightarrow B)\Rightarrow A)\Rightarrow A$, true in classical logic (truth table), has no inhabitant; control operators (like call/cc in Scheme) must be added to extend the correspondence to classical logic (Griffin, 1990). Deciding whether a simple type has an inhabitant is $\mathsf{PSPACE}$-complete (Statman, 1979), whereas checking that a given term has a given type takes polynomial time. System F and its extensions are presented further on.

Beyond simple types: from System F to the calculus of constructions

By enriching types, one obtains languages able to express all of usual mathematics. These are the languages used in proof assistants, software that checks each step of a proof, and that is used today to check the proofs produced by artificial intelligences.

Simply typed λ-calculus is total, but poor: its functions on Church numerals are barely extended polynomials. It can be enriched without losing termination, by allowing types to vary. Each enrichment gives a more expressive total language and, through Curry-Howard, a stronger logic. The summit of this construction, the calculus of constructions, is the theoretical core of today’s proof assistants.

Definition
System F (Girard, 1972; Reynolds, 1974)

The types of System F add to the simple types type variables $\alpha,\beta,\dots$ and quantification over types: $A,B::=\alpha\mid A\to B\mid\forall\alpha.A$. The terms add type abstraction $\Lambda\alpha.M$ and application to a type $M\,B$, with two rules:

$$\frac{\Gamma\vdash M:A\quad(\alpha\text{ not free in }\Gamma)}{\Gamma\vdash\Lambda\alpha.M:\forall\alpha.A}\qquad\frac{\Gamma\vdash M:\forall\alpha.A}{\Gamma\vdash M\,B:A[\alpha:=B]}$$

and the computation rule $(\Lambda\alpha.M)\,B\to M[\alpha:=B]$. Results quoted for information: every term of System F is strongly normalizing (Girard, 1972, by the method of reducibility candidates), and the functions $\N\to\N$ representable in F are exactly the recursive functions whose totality is provable in second-order arithmetic (Girard, 1972).

In plain words. System F makes it possible to write programs that work for all types at once, like a “sort” function that sorts numbers as well as words. Everything still terminates.

This is called polymorphism, and the languages Java, OCaml or Haskell use it every day. In System F, one no longer even needs numbers or lists “supplied in advance”: everything is built with functions.

System F is very powerful: it computes the Ackermann function and far beyond. But like every language in which everything halts, it does not contain its own interpreter (see above). There is a surprising logical consequence: a very strong mathematical theory (second-order arithmetic) is unable to prove that all programs of System F halt, although it is true. Girard proved it using an even stronger principle.

Integers. Set $\mathrm{Nat}=\forall\alpha.(\alpha\to\alpha)\to\alpha\to\alpha$, and, as for the Church numerals, $\mathbf n=\Lambda\alpha.\lambda f{:}\alpha\to\alpha.\lambda x{:}\alpha.\,f^n\,x$. The successor is $\mathsf S=\lambda n{:}\mathrm{Nat}.\Lambda\alpha.\lambda f.\lambda x.\,f\,(n\,\alpha\,f\,x)$. An integer is an iterator, usable at any type: $\mathbf n\,B\,g\,b=g^n(b)$ for every type $B$. In simply typed λ-calculus, by contrast, a Church numeral has a single type, fixed once and for all, and one can iterate only at that type.

Ackermann. Iterate at type $\mathrm{Nat}\to\mathrm{Nat}$, as in System T, but without a primitive recursor:

$$H=\lambda f{:}\mathrm{Nat}\to\mathrm{Nat}.\,\lambda n{:}\mathrm{Nat}.\ (\mathsf S\,n)\,\mathrm{Nat}\,f\,\mathbf 1,\qquad \mathsf{ack}=\lambda m{:}\mathrm{Nat}.\ m\,(\mathrm{Nat}\to\mathrm{Nat})\,H\,\mathsf S.$$

We have $H:(\mathrm{Nat}\to\mathrm{Nat})\to\mathrm{Nat}\to\mathrm{Nat}$ and $H\,f\,n=f^{n+1}(1)$, so $\mathsf{ack}\,\mathbf 0=\mathsf S$ and $\mathsf{ack}\,\mathbf{m+1}=H(\mathsf{ack}\,\mathbf m)$, which is the relation $A(m+1,n)=A(m,\cdot)^{n+1}(1)$ of Péter’s function. The term $\mathsf{ack}$ has type $\mathrm{Nat}\to\mathrm{Nat}\to\mathrm{Nat}$: it is the application of $m$ to the type $\mathrm{Nat}\to\mathrm{Nat}$, impossible with simple types, that takes us beyond the primitive recursive functions.

Logic. Through Curry-Howard, F corresponds to second-order propositional logic, where one can quantify over propositions. The other connectives are defined in it: $\bot=\forall\alpha.\alpha$, $A\wedge B=\forall\alpha.(A\to B\to\alpha)\to\alpha$, $A\vee B=\forall\alpha.(A\to\alpha)\to(B\to\alpha)\to\alpha$. Normalization implies that no closed term has type $\bot$: the logic is consistent.

The program logique.py writes these terms in Python, erasing the types (Python does not check them), and checks that $\mathsf{ack}\,\mathbf m\,\mathbf n$ agrees with Péter’s definition for $m,n<4$; for example $\mathsf{ack}\,\mathbf 3\,\mathbf 3=\mathbf{61}$. Result quoted for information: recovering the erased types, that is, deciding whether a pure λ-term is typable in F, is undecidable (Wells, 1994). This is why languages based on polymorphism, such as OCaml and Haskell, restrict themselves to fragments where type inference is decidable (the Hindley-Milner system), or require annotations.

Definition
Barendregt’s λ-cube (1991)

In simply typed λ-calculus, terms depend on terms: $\lambda x{:}A.\,M$. Three other kinds of dependency can be added, independently of one another:

  • terms depending on types (polymorphism: $\Lambda\alpha.M$);
  • types depending on types (type operators: $\lambda\alpha.\,\alpha\to\alpha$, a function from types to types);
  • types depending on terms (dependent types: $\mathrm{Vec}\,n$, the type of lists of length $n$).

The $2^3=8$ combinations form the vertices of a cube. The origin is $\lambda{\to}$ (simple types), polymorphism alone gives $\lambda2$ (System F), operators alone $\lambda\underline\omega$, dependent types alone $\lambda P$ (the language LF); the vertex opposite the origin, with all three dependencies, is the calculus of constructions $\lambda C$ (Coquand and Huet, 1988). Result quoted for information: the eight systems are strongly normalizing, hence total and, through Curry-Howard, consistent.

In plain words. Types can be enriched in three independent ways. The eight possible combinations are arranged at the vertices of a cube. The richest vertex, the calculus of constructions, serves as the basis of modern proof software.

The bottom-left corner is the simplest typed λ-calculus. Going up in the picture is allowing a function that works for all types (polymorphism). Going right is allowing types to speak of values, such as “list of length 5” or “prime number”. Going into depth is allowing computation on types themselves. Each vertex is also a logic, more and more expressive: the higher one goes in the cube, the more statements one can write and functions one can program, while keeping the guarantee that everything halts.

In Barendregt’s presentation, there are two sorts: $\ast$ (the type of types, where propositions live) and $\square$ (where $\ast$ itself lives). The dependent product $\Pi x{:}A.\,B$ generalizes both the arrow ($A\to B$ when $x$ does not occur in $B$) and the quantifier ($\forall\alpha.B$ when $A=\ast$). A rule $(s_1,s_2)$ allows $\Pi x{:}A.B:s_2$ when $A:s_1$ and $B:s_2$. Simply typed λ-calculus has only the rule $(\ast,\ast)$; one gets $\lambda2$ by adding $(\square,\ast)$, $\lambda\underline\omega$ by adding $(\square,\square)$, $\lambda P$ by adding $(\ast,\square)$, and $\lambda C$ with all four rules.

Remark
The calculus of constructions and proof assistants

In the calculus of constructions, a statement such as “for every integer $n$, $n+0=n$” is a type $\Pi n{:}\mathrm{Nat}.\ n+0=n$, and a proof is a function that associates with each $n$ a proof of $n+0=n$. Checking a proof is checking the type of a term, which is decidable. Today’s proof assistants rest on extensions of this calculus (results and facts quoted for information):

  • Rocq (called Coq until 2025) rests on the calculus of inductive constructions (Coquand and Paulin-Mohring, late 1980s), which adds inductive types (integers, lists, trees defined by their constructors) and a hierarchy of universes. Website: rocq-prover.org; to get started, the online course Software Foundations.
  • Lean (Leonardo de Moura, since 2013; Lean 4 since 2021) rests on a closely related dependent type theory, with inductive types and universes. Its community library Mathlib covers a large part of undergraduate mathematics and some graduate mathematics. Website: lean-lang.org; to get started, Theorem Proving in Lean 4 and the Natural Number Game.
  • Agda rests on Martin-Löf type theory (1972), another dependent type theory, predicative.

Some achievements: the four colour theorem (Gonthier, 2005) and the Feit-Thompson theorem (Gonthier et al., 2012) in Coq; the verified C compiler CompCert (Leroy, in Coq); the Liquid Tensor Experiment (2022), which verified in Lean a hard theorem of Clausen and Scholze; the determination of the value of the 5-state busy beaver (2024), in Coq.

In plain words. In the calculus of constructions, a mathematical statement is a type, and a proof is a program of this type. Proof software such as Rocq (formerly Coq) or Lean rests on this principle.

As in the whole cube, every accepted program halts, and this is precisely what guarantees that the logic does not contradict itself. It is also why Rocq and Lean reject a recursive definition if they do not see why it halts: sometimes one has to prove that a computation terminates before being allowed to write it.

This software is constructive: proving “there exists a number that…” amounts to providing the computation of this number. Non-constructive principles can be added, such as “every statement is true or false”; proofs remain checkable, but they no longer contain a computation to run.

Remark
Checking proofs produced by AIs

Facts quoted for information. Artificial intelligence systems now produce formal proofs, written in Lean, which Lean’s kernel checks. In 2024, AlphaProof (Google DeepMind) solved several problems of the International Mathematical Olympiad this way; in 2025, several systems announced Lean-formalized solutions to problems from that year’s competition. The same pattern is used in research: collaborative projects, such as the one Terence Tao launched in 2024 on the equational theories of magmas, combine human contributions, automated provers and verification in Lean.

In plain words. Artificial intelligences now write proofs in the language of software such as Lean, which checks them. The machine that checks does not need to trust the one that searches.

Everything rests on the asymmetry already met: checking a proof is always possible, mechanically, by a small program written to be reread by humans; finding a proof is not (see checking is decidable, finding is not). One can therefore let an AI search by unpredictable and fallible means, and trust only the checker. If the AI invents a false proof, it is simply rejected.

Three limits remain. The checker verifies that the proof proves the written statement, not that the written statement says what was meant: this translation remains human work. One must believe that the checker itself and the theory it uses do not contradict themselves, which the theory cannot prove on its own (second incompleteness theorem). Finally, a checked proof may be unreadable: knowing that something is true is not yet understanding why.

★Exercise 1 — Typing terms

Give a type to each of the following terms, or explain why it has none: (a) $\lambda x.\lambda y.\,y\,x$; (b) $\lambda f.\lambda g.\lambda x.\,g\,(f\,x)$; (c) $\lambda x.\,x\,x$; (d) $\lambda f.\lambda x.\,f\,(f\,x)$. Which logical formula does each prove?

Solution
  • (a) $A\to(A\to B)\to B$: from $A$ and $A\Rightarrow B$, deduce $B$ (modus ponens, as a statement).
  • (b) $(A\to B)\to(B\to C)\to A\to C$: transitivity of implication; the term is function composition.
  • (c) has no type (see the definition): the type of $x$ would have to be both $A$ and $A\to B$.
  • (d) $(A\to A)\to A\to A$: this is the Church numeral $\mathbf 2$. The formula $(A\Rightarrow A)\Rightarrow(A\Rightarrow A)$ has infinitely many detour-free proofs, one per integer: the proofs of a single formula are not interchangeable, they have computational content.
★Exercise 2 — A syllogism decided mechanically

Is the sentence “if every $P$ is $Q$ and some $P$ is $R$, then some $Q$ is $R$” valid? And “if some $P$ is $Q$ and some $Q$ is $R$, then some $P$ is $R$”? For the second, give a countermodel and say at most how many elements need to be tried.

Solution

The first is valid: if $a$ is $P$ and $R$, it is $Q$ (since every $P$ is $Q$), so $a$ is $Q$ and $R$. The second is not: domain $\{1,2\}$, $P=\{1\}$, $Q=\{1,2\}$, $R=\{2\}$. There are three predicates, so by Löwenheim’s theorem it suffices to try domains with at most $2^3=8$ elements; here two suffice. The program logique.py finds a countermodel of the same kind for the neighbouring sentence of the text.

★★Exercise 3 — Inhabitants and non-inhabitants

(a) Find a closed term of type $(A\to B\to C)\to B\to A\to C$. (b) Show that no closed term has type $(A\to B)\to A$, where $A$ and $B$ are distinct atomic types.

Solution

(a) $\lambda f.\lambda b.\lambda a.\,f\,a\,b$: swap the order of the hypotheses.

(b) By normalization, it would suffice to consider a closed normal term $M$ of this type. A normal term has the form $\lambda x_1\cdots\lambda x_n.\,y\,M_1\cdots M_k$. The type $(A\to B)\to A$ has a single arrow “at the head”: $M=\lambda f.\,N$ with $f:A\to B$ and $N:A$ normal (if $n\ge2$, the type would need two arrows at the head; and $n=0$ is impossible for a closed term). Since $A$ is atomic, $N=y\,M_1\cdots M_k$ with $y$ free in $N$, so $y=f$. But $f\,M_1\cdots M_k$ has type $B$ if $k=1$ and type $A\to B$ if $k=0$, never $A$ (and $k\ge2$ is impossible, since $B$ is not an arrow). Contradiction. Logically: $(A\Rightarrow B)\Rightarrow A$ is not provable, which can also be seen from the truth table ($A$ false, $B$ false makes the formula false).

★★Exercise 4 — Addition and multiplication in System T

Write in System T terms $\mathsf{add},\mathsf{mul}:\mathbf N\to\mathbf N\to\mathbf N$, then the function $\mathsf{exp}\,m\,n=2^n$, using only the recursor at type $\mathbf N$. Why does Ackermann need the recursor at a higher type?

Solution

$\mathsf{add}=\lambda m.\lambda n.\ \mathsf R_{\mathbf N}\,m\,(\lambda k.\lambda r.\,\mathsf S\,r)\,n$; $\mathsf{mul}=\lambda m.\lambda n.\ \mathsf R_{\mathbf N}\,0\,(\lambda k.\lambda r.\,\mathsf{add}\,r\,m)\,n$; $\mathsf{exp}=\lambda n.\ \mathsf R_{\mathbf N}\,(\mathsf S\,0)\,(\lambda k.\lambda r.\,\mathsf{add}\,r\,r)\,n$. Every primitive recursive function is defined this way, with the recursor $\mathsf R_{\mathbf N}$ alone; conversely, and this is a result quoted for information, this fragment of System T defines only primitive recursive functions; but the Ackermann function is not primitive recursive. In the definition of the text, the recursion on $m$ builds not an integer but a function $\mathsf{ack}\,m:\mathbf N\to\mathbf N$: it is a recursion at type $\mathbf N\to\mathbf N$.

★★★Exercise 5 — Why a total language has no fixed point

(a) Show that the fixed-point combinator $\mathsf Y$ of λ-calculus is not typable. (b) Add to simply typed λ-calculus a constant $\mathsf{fix}_A:(A\to A)\to A$ with the rule $\mathsf{fix}\,f\to f\,(\mathsf{fix}\,f)$. Show that every type becomes inhabited, and deduce that the corresponding logic is inconsistent.

Solution

(a) $\mathsf Y=\lambda f.(\lambda x.f(x\,x))(\lambda x.f(x\,x))$ contains the subterm $x\,x$, which is not typable (same argument as for $\lambda x.\,x\,x$); but every subterm of a typable term is typable. Another argument: $\mathsf Y\,(\lambda x.x)$ has no normal form, which normalization forbids for a typable term.

(b) $\mathsf{fix}_A\,(\lambda x.x)$ is a closed term of type $A$, for every $A$, in particular for an atomic type $o$. Through the Curry-Howard correspondence, $\mathsf{fix}$ is the “axiom” $(A\Rightarrow A)\Rightarrow A$, which proves anything: the logic is inconsistent. This is the exact price of universality. Ordinary programming languages have a $\mathsf{fix}$ (general recursion), so their types are not reliable statements; proof assistants forbid it, and accept only recursions whose termination they check.

★★Exercise 6 — Booleans and pairs in System F

In System F, set $\mathrm{Bool}=\forall\alpha.\alpha\to\alpha\to\alpha$. (a) Write two closed terms $\mathsf{true},\mathsf{false}:\mathrm{Bool}$ and a term $\mathsf{and}:\mathrm{Bool}\to\mathrm{Bool}\to\mathrm{Bool}$. (b) Write the type $A\times B$ of pairs, a constructor $\mathsf{pair}:A\to B\to A\times B$ and the first projection.

Solution

(a) $\mathsf{true}=\Lambda\alpha.\lambda x{:}\alpha.\lambda y{:}\alpha.\,x$, $\mathsf{false}=\Lambda\alpha.\lambda x{:}\alpha.\lambda y{:}\alpha.\,y$. A Boolean is an “if then else”: $b\,C\,u\,v$ equals $u$ if $b=\mathsf{true}$, $v$ if $b=\mathsf{false}$. Hence $\mathsf{and}=\lambda a{:}\mathrm{Bool}.\lambda b{:}\mathrm{Bool}.\ a\,\mathrm{Bool}\,b\,\mathsf{false}$: if $a$ is true, the result is $b$, otherwise false.

(b) $A\times B=\forall\alpha.(A\to B\to\alpha)\to\alpha$: a pair is what supplies its two components to any function of two arguments. $\mathsf{pair}=\lambda a{:}A.\lambda b{:}B.\Lambda\alpha.\lambda k{:}A\to B\to\alpha.\,k\,a\,b$, and $\pi_1=\lambda p{:}A\times B.\ p\,A\,(\lambda a{:}A.\lambda b{:}B.\,a)$. One recognizes the definition of $A\wedge B$ given in the text: through Curry-Howard, a proof of $A\wedge B$ is a pair of proofs.

★★★Exercise 7 — What System F does not compute

Show that there is a total computable function $\N\to\N$ that is not representable in System F, without using Girard’s theorem. Deduce, using that theorem, that second-order arithmetic does not prove the normalization of System F.

Solution

Number the closed terms of type $\mathrm{Nat}\to\mathrm{Nat}$: $t_0,t_1,\dots$ (enumerate the terms and keep those having this type, which is decidable since terms carry their type annotations). Let $d(n)$ be the integer whose Church numeral is the normal form of $t_n\,\mathbf n$, plus $1$. Since F normalizes, and a closed normal form of type $\mathrm{Nat}$ is a Church numeral (result quoted for information, analogous to the shape of normal terms in the corollary), $d$ is computable and total: reduce $t_n\,\mathbf n$ to its normal form. If $d$ were represented by $t_k$, we would have $d(k)=d(k)+1$. This is the argument of the theorem on total languages.

By Girard’s theorem, a function whose totality second-order arithmetic proves is representable in F. So second-order arithmetic does not prove that $d$ is total. But the normalization of F implies, in this arithmetic, the totality of $d$: so it cannot prove the normalization of F. Girard’s proof (by reducibility candidates) uses a comprehension that goes beyond formalized second-order arithmetic.
