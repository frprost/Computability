The Turing machine is not the only device capable of computing everything. This chapter presents systems that look much poorer and are capable of it too: a machine that has only two counters which it can increase, decrease and test; a list of fractions that one multiplies; a row of black and white cells that change according to a local rule.

The phenomenon is general: as soon as a system makes it possible to store an arbitrary amount of information and to transform it according to conditional rules, it becomes universal. This is why universality, and therefore undecidability, is found almost everywhere, even in games and physical models.

Counter machines

A counter machine has a few counters, like abacuses, which it can increase by 1, decrease by 1, or test for zero. With only two counters, it can compute everything, provided the data are coded in a clever way.

Theorem
Universality of two-counter machines (Minsky, 1961)

A counter machine has a finite number of registers holding natural numbers and a program made of numbered instructions of two kinds: $\mathrm{INC}(r,j)$ (add 1 to register $r$, go to instruction $j$) and $\mathrm{DEC}(r,j,k)$ (if $r>0$, subtract 1 and go to $j$; otherwise go to $k$). Every computable function is computable by a counter machine, and even by a machine with two counters, provided the input $x$ is coded by $2^x$ and the output $y$ by $2^y$.

In plain words. A machine that has only two counters, which it can increase by 1, decrease by 1 and compare with zero, can compute everything a Turing machine computes. The data only need to be coded cleverly in the counters.

Imagine two boxes of pebbles. All one can do is add a pebble, remove one, and look whether a box is empty. That is enough to compute everything! Memory need not be neatly organized, with cells and addresses; it only needs to be unbounded.

Step 1: any number of counters. A counter machine $M$ computes $f:\N^n\rightharpoonup\N$ if, started at instruction $1$ with $x_1,\dots,x_n$ in counters $r_1,\dots,r_n$ and $0$ in the others, it reaches the halting instruction if and only if $f(\vec x)$ is defined, and then $r_0$ contains $f(\vec x)$ (the other counters contain anything). First we program a few fragments, which are chained by replacing their “end” with the next instruction:

  • $\mathrm{CLR}(r)$, which sets $r$ to zero: the instruction $\mathrm{DEC}(r,\text{itself},\text{end})$;
  • $\mathrm{COPY}(r,s;t)$, which copies $r$ into $s$ without destroying $r$, using an auxiliary counter $t$: $\mathrm{CLR}(s)$, $\mathrm{CLR}(t)$, then while $\mathrm{DEC}(r)$ succeeds, $\mathrm{INC}(s)$ and $\mathrm{INC}(t)$; then while $\mathrm{DEC}(t)$ succeeds, $\mathrm{INC}(r)$.

A machine uses only finitely many counters; those of a machine $G$ can be renamed so as to be distinct from all those of a given program, and we write “run $G$ on $u_1,\dots,u_p$” for the fragment that sets all counters of $G$ to zero, copies $u_1,\dots,u_p$ into its input counters, then executes $G$ with its halt replaced by a jump to what follows; it terminates if and only if $G$ halts, and the output counter of $G$ then contains the result. We then show, by induction on the definition of recursive functions, that every recursive function is computed by a counter machine:

  • base functions: $\mathrm{CLR}(r_0)$ followed by $m$ times $\mathrm{INC}(r_0)$ for the constant $m$; $\mathrm{COPY}(r_1,r_0;t)$ then $\mathrm{INC}(r_0)$ for the successor; $\mathrm{COPY}(r_i,r_0;t)$ for the projection;
  • substitution $\sigma[g,h_1,\dots,h_k]$: run $H_1,\dots,H_k$ in turn on $\vec x$, then $G$ on their $k$ outputs, and copy the output of $G$ into $r_0$. If some $h_i(\vec x)$ is undefined, $H_i$ does not halt, and neither does the machine;
  • recursion $\rho[g,h]$, the recursion argument being in $r_1$ and the others in $r_2,\dots$: run $G$ on $r_2,\dots$ and copy its output into a counter $a$; set $i$ to zero and copy $r_1$ into $c$; then while $\mathrm{DEC}(c)$ succeeds: run $H$ on $(i,a,r_2,\dots)$, copy its output into $a$, $\mathrm{INC}(i)$. At the end, $a$ contains $f(r_1,\dots)$ by induction on the number of rounds;
  • minimization $\mu[g]$: set $y$ to zero; repeat: run $G$ on $(\vec x,y)$; if $\mathrm{DEC}$ of the output counter fails (the value is $0$), copy $y$ into $r_0$ and halt, otherwise $\mathrm{INC}(y)$ and start again. The machine tries $y=0,1,2,\dots$ in order, and halts only if all the values $g(\vec x,z)$, $z<y$, are defined and nonzero and $g(\vec x,y)=0$: this is the definition of $\mu$.

Since the computable functions are the recursive functions (equivalence of models), every computable function is computed by a counter machine. Adding a final fragment if necessary, we also assume that on halting the result is in $r_1$ and all other counters are zero (copy $r_0$ into $r_1$, then empty the others).

Step 2: two counters. Let $M$ be such a machine, with counters $r_1,\dots,r_k$, and $p_1=2,p_2=3,\dots,p_k$ the first $k$ primes. The contents $(c_1,\dots,c_k)$ of its counters are coded by the single number $N=p_1^{c_1}\cdots p_k^{c_k}$, stored in a counter $A$, the other counter $B$ being $0$. Each instruction of $M$ is replaced by a fragment that starts and ends with $B=0$:

  • $\mathrm{INC}(r,j)$, with $p=p_r$: while $\mathrm{DEC}(A)$ succeeds, do $p$ times $\mathrm{INC}(B)$; then while $\mathrm{DEC}(B)$ succeeds, $\mathrm{INC}(A)$; go to fragment $j$. This gives $A=pN$, that is, $c_r+1$.
  • $\mathrm{DEC}(r,j,k)$, with $p=p_r$: divide $A$ by $p$ with $p$ instructions $d_1,\dots,d_p$; $d_i$ is $\mathrm{DEC}(A,d_{i+1},R_{i-1})$, and after $d_p$ succeeds we do $\mathrm{INC}(B)$ and return to $d_1$. When a $\mathrm{DEC}$ fails at $d_i$, $B$ contains the quotient $\lfloor N/p\rfloor$ and state $R_{i-1}$ knows the remainder $\rho=i-1$. If $\rho=0$, $p$ divides $N$, so $c_r>0$: transfer $B$ into $A$, which gives $A=N/p$ ($c_r-1$), and go to fragment $j$. If $\rho>0$, then $c_r=0$: rebuild $A=pB+\rho$ ($\rho$ times $\mathrm{INC}(A)$, then while $\mathrm{DEC}(B)$ succeeds, $p$ times $\mathrm{INC}(A)$), that is, $A=N$, and go to fragment $k$.
  • halting stays halting.

Each fragment thus transforms the code of the configuration of $M$ before the instruction into the code of the configuration after. The resulting two-counter machine, started on $(2^x,0)$, that is, on the code of $(x,0,\dots,0)$, halts if and only if $M$ halts, and then on $(2^{f(x)},0)$. The exponential coding of inputs and outputs is indispensable: this is Schroeppel’s theorem below.

Theorem
Two counters do not compute 2^x (Schroeppel, 1972)

Consider a two-counter machine which, started on $(x,0)$, halts for every $x$, with $f(x)$ in its first counter, where $f$ is injective. Then there are integers $x_0\ge0$, $L\ge1$ and $G\ge0$ such that $f(x_0+kL)=f(x_0)+kG$ for every $k\ge0$. In particular, no two-counter machine computes $x\mapsto2^x$, or $x\mapsto x^2$, on the input $x$ coded directly.

In plain words. With two counters, if the starting number is given as it is, one cannot compute 2 multiplied by itself that number of times. The clever coding of the data is therefore indispensable.

With two boxes of pebbles, one is almost always empty when the other is full: the machine really keeps only one number in mind. All it can do with it, in the long run, is multiply it by a fixed fraction and add a fixed quantity to it. It cannot itself manufacture very rapid growth; this must be supplied from the start, in the way the input is written.

The instructions are numbered $1,\dots,m$ and a configuration is a triple $(i,a,b)$. It is null if $a=0$ or $b=0$.

Phase lemma. For each instruction $i$, there are integers $T_i$ and $d_i\ge1$ such that one of the following two things happens for all $n\ge T_i$: (α) the computation starting from $(i,n,0)$ never reaches, after at least one step, a null configuration or a halt; (β) it reaches a first one, $C(n)$, whose instruction $i'$ does not depend on $n$, and there is $(u,v)\in\N^2$ independent of $n$ such that $C(n+d_i)=C(n)+(0,u,v)$, with $u=0$ if the first counter of $C(n)$ is zero and $v=0$ if the second is. The same holds, symmetrically, starting from $(i,0,n)$.

Proof. Start from $(i,n,0)$ with $n\ge2$. If instruction $i$ is $\mathrm{INC}(a)$, $\mathrm{DEC}(a)$ or $\mathrm{DEC}(b)$ (which fails), or the halt, the next configuration is null or halting, of the form $(i',n+c,0)$ with $c\in\{-1,0,1\}$: (β) holds with $d_i=1$ and $(u,v)=(1,0)$. There remains the case $\mathrm{INC}(b)$, which leads to $(j,n,1)$. As long as both counters stay positive, every $\mathrm{DEC}$ succeeds: the sequence of instructions $j=j_0,j_1,j_2,\dots$ depends only on $j$, and after $s$ steps the counters are $n+A(s)$ and $1+B(s)$, where $A(s)$ and $B(s)$ do not depend on $n$ and satisfy $|A(s)|\le s$. If this sequence reaches the halt, let $s_h$ be the step at which this happens; if $1+B(s)$ vanishes, let $s_b$ be the first step at which this happens. These numbers do not depend on $n$.

  • If $s_h$ or $s_b$ exists, let $s^*$ be the smaller of the two. For $n>s^*$, counter $a$ has not vanished before $s^*$, so $C(n)$ is the configuration at step $s^*$, $(j_{s^*},n+A(s^*),1+B(s^*))$: (β) with $d_i=1$, $(u,v)=(1,0)$.
  • Otherwise the sequence $(j_s)$ is infinite and, having only $m$ possible values, it is eventually periodic: there are $p$ and $\ell\ge1$ such that $j_{s+\ell}=j_s$ for $s\ge p$. The variations of the counters over one period are therefore constant: $A(s+\ell)=A(s)+A_c$ and $B(s+\ell)=B(s)+B_c$ for $s\ge p$. Since $1+B(s)$ never vanishes, $B_c\ge0$. If $A_c\ge0$, then $A(s)\ge-(p+\ell)$ for all $s$, and for $n>p+\ell$ counter $a$ never vanishes either: this is (α). If $A_c<0$, set $d_i=-A_c$, and take $n>p+\ell$; let $h(n)$ be the first step at which $n+A(s)=0$ (it exists, since $A(s)\to-\infty$), so that $h(n)\ge p+\ell$. For $n'=n+d_i$: at steps $s<p+\ell$, $n'+A(s)\ge n'-(p+\ell)>0$; at steps $s+\ell$ with $s\ge p$, $n'+A(s+\ell)=n+A(s)$. The first zero of $a$ for $n'$ is therefore at step $h(n)+\ell$, with the same instruction $j_{h(n)+\ell}=j_{h(n)}$, and $b$ there equals $1+B(h(n))+B_c$. This is (β) with $(u,v)=(0,B_c)$.

Take $T_i$ larger than $2$, $s^*$ and $p+\ell$. By induction, $C(n+t\,d_i)=C(n)+t\,(0,u,v)$ for all $t\ge0$. $\square$

Proof of the theorem. Let $D$ be a common multiple of all the $d_i$ (for both sides) and $T$ the largest of the $T_i$. Call small a null configuration both of whose counters are $<T$; there are finitely many. If the computation starting from $(1,x,0)$ passes through a small configuration, the rest of the computation, hence $f(x)$, is determined by that configuration: these $x$ have only finitely many values $f(x)$, and since $f$ is injective, there are finitely many of them. Choose $x_0\ge T$ whose computation passes through no small configuration. This computation halts; write $C_0=(1,x_0,0)$, then $C_1,\dots,C_N$ for its successive null configurations, and $C_{N+1}$ for its halting configuration. Each $C_j$, $j\le N$, has one zero counter and the other, written $n_j$, at least $T$; and $C_{j+1}$ is the first null or halting configuration following $C_j$.

Set $L=D^{N+2}$ and $x_k=x_0+kL$. We show by induction on $j\le N+1$ that the $j$-th null (or halting) configuration of the computation starting from $x_k$ is $C_j+k\,g_j\,e_j$, where $e_j$ is a fixed vector with nonnegative integer coordinates, zero on the zero counter of $C_j$, and $g_j$ is an integer divisible by $D^{N+2-j}$. For $j=0$, $g_0=L$ and $e_0=(0,1,0)$. If it holds for $j\le N$, the nonzero value $n_j+kg_j$ is $\ge T$, and $kg_j$ is a multiple of $d_{i_j}$; the phase lemma, applied $kg_j/d_{i_j}$ times, gives the next configuration $C_{j+1}+k\,(g_j/d_{i_j})\,(0,u,v)$, and $g_j/d_{i_j}$ is divisible by $D^{N+1-j}$. For $j=N+1$, we get that the computation starting from $x_k$ halts, with first counter equal to $f(x_0)+kG$, where $G\ge0$ does not depend on $k$.

For $f(x)=2^x$, we would have $2^{x_0+2L}-2^{x_0}=2\,(2^{x_0+L}-2^{x_0})$, that is, $(2^L-1)^2=0$, impossible for $L\ge1$. For $f(x)=x^2$, we would have $4x_0L+4L^2=4x_0L+2L^2$, impossible too. Schroeppel gave the first result of this type in 1972; the proof above shows more generally that the sequence $k\mapsto f(x_0+kL)$ is affine.

Theorem
Two counters directly simulate a tape (Minsky, 1961)

Let $Z$ be a Turing machine whose alphabet has $b\ge2$ symbols, numbered from $0$ to $b-1$, the blank bearing the number $0$. If the head is at $p$ on the tape $\tau$, let

$$d=\sum_{i\ge0}c\big(\tau(p+i)\big)\,b^i,\qquad g=\sum_{i\ge0}c\big(\tau(p-1-i)\big)\,b^i,$$

where $c(s)$ is the number of the symbol $s$ (these sums are finite). One can build, from $Z$, a machine with three counters $g,d,t$ which, starting from $(g,d,t)=(g_0,d_0,0)$, halts if and only if $Z$ halts from the corresponding configuration, and then with $(g,d)$ equal to the coding of the final configuration and $t=0$. Then a machine with two counters which, starting from $(2^{g_0}3^{d_0},0)$, does the same with $(2^g3^d,0)$.

In plain words. The tape of a Turing machine can be stored in two numbers: one for what is to the left of the head, the other for the scanned cell and what lies to its right. A machine that can only add 1, subtract 1 and test for zero can then imitate the Turing machine step by step.

The idea is that of writing numbers. A tape that contains only blanks and strokes is written as a sequence of 0s and 1s, that is, as a number in binary. The units digit of the right-hand number is the scanned cell: to read it, it suffices to know whether the number is even or odd. Moving the head one cell to the right means removing this digit from the right-hand number (dividing it by 2) and adding it to the left-hand number (multiplying it by 2 and adding the digit). Dividing and multiplying by 2 are done with repeated additions and subtractions of 1, using a third counter as scratch.

It remains to go from three counters to two. The three numbers are stored in a single one, thanks to prime numbers: the triple (5, 2, 0) becomes 25 × 32 × 50 = 288. Adding 1 to the second number is multiplying by 3; testing whether it is zero is looking whether 288 is divisible by 3. The second counter serves as scratch for these multiplications and divisions. The price is staggering: to add 2 and 1, the two-counter machine makes a number of steps with 28 digits.

We write fragments: pieces of program that begin at a label and end with a jump to an “end” label. An unconditional jump to $j$ is written $\mathrm{DEC}(z,j,j)$ on a counter $z$ that is never modified, which is always $0$.

  • $\mathrm{TRANS}(x,y,m)$, which does $y:=y+m\,x$ and $x:=0$: the instruction $\mathrm{DEC}(x,\cdot,\text{end})$ followed by $m$ times $\mathrm{INC}(y)$, with a return to the $\mathrm{DEC}$.
  • $\mathrm{ADD}(x,r)$, which does $x:=x+r$ for a constant $r$: $r$ instructions $\mathrm{INC}(x)$.
  • $\mathrm{DIV}(x,y,b)$, which does $y:=y+\lfloor x/b\rfloor$, $x:=0$, and exits to one of $b$ labels according to the remainder: the instructions $D_1,\dots,D_b$, where $D_k=\mathrm{DEC}(x,D_{k+1},R_{k-1})$ and where $D_{b+1}$ is $\mathrm{INC}(y)$ followed by a return to $D_1$. If $x=qb+r$ with $r<b$, the machine makes $q$ complete rounds, then the $\mathrm{DEC}$ of $D_{r+1}$ fails and one exits at $R_r$.

Three counters. For each state $q$ of $Z$, the fragment $\mathrm{Read}_q$ is $\mathrm{DIV}(d,t,b)$: at the exit $R_r$, the scanned cell is the symbol $s$ with number $r$, $d=0$ and $t$ contains the rest of the tape to the right, $\lfloor d/b\rfloor$. Each row transforms the coding $(g,d)$ of the configuration into that of the next configuration, with $t=0$ before and after: moving right removes the units digit of $d$ and places it as the units digit of $g$, which shifts the tape by one cell; moving left does the converse; writing changes the units digit of $d$. Since the blank is $0$, blanks added at the edges do not change the numbers. The three-counter machine (plus $z$) therefore halts exactly when $Z$ halts, with the coding of the final configuration. For a machine whose alphabet is $\{B,1\}$, we have $b=2$: $g$ and $d$ are the two halves of the tape read as binary numbers.

Two counters. We apply to this machine step 2 of the previous theorem: the contents $(g,d,t,z)$ are stored in $A=2^g3^d5^t7^z$, $B$ being $0$ between two fragments; $\mathrm{INC}$ of a counter becomes a multiplication of $A$ by the corresponding prime, $\mathrm{DEC}$ a division with examination of the remainder. The jumps $\mathrm{DEC}(z,j,j)$ simply become $\mathrm{DEC}(B,j,j)$, since $B=0$. Since $z$ and $t$ are $0$ at the start and at halting, the machine starts from $2^{g_0}3^{d_0}$ and halts on $2^g3^d$.

Cost. A step of $Z$ costs a number of steps proportional to $g+d$, hence exponential in the length of the tape, for three counters; an $\mathrm{INC}$ with three counters costs a number of steps proportional to $A$ with two counters, hence a second exponential. This is the price of the coding, and Schroeppel’s theorem shows that it cannot be avoided.

# ---- fragments: each begins at the given label and jumps to "end"
def transfer(self, src, dst, factor, start, end):
    """dst += factor * src ; src := 0."""
    self.here(start)
    body = [self.fresh() for _ in range(factor)]
    self.dec(src, body[0] if factor else start, end)
    for k, e in enumerate(body):
        self.here(e)
        self.inc(dst, body[k + 1] if k + 1 < factor else start)

def add(self, r, n, start, end):
    """r += n (n constant)."""
    if n == 0:
        self.here(start)
        self.dec_zero(end)
        return
    lab = [start] + [self.fresh() for _ in range(n - 1)] + [end]
    for k in range(n):
        self.here(lab[k])
        self.inc(r, lab[k + 1])

def dec_zero(self, end):
    # "go to end": a jump is simulated by an instruction on a reserved counter, always zero
    self.dec(Z, end, end)

def divide(self, src, quot, b, start, exits):
    """quot += src // b ; src := 0 ; jumps to exits[remainder]."""
    stages = [start] + [self.fresh() for _ in range(b)]
    for k in range(b):
        self.here(stages[k])
        self.dec(src, stages[k + 1], exits[k])
    self.here(stages[b])
    self.inc(quot, start)

def three_counters(machine):
    """Translates a Turing machine into a counter machine with counters g, d, t (plus Z, always zero).
    Returns (program, codes of the symbols, base b)."""
    codes = symbol_codes(machine)
    b = max(2, len(codes))
    symb = {c: s for s, c in codes.items()}
    a = Assembler()
    states = sorted(machine.states())
    start = {q: "read_" + q for q in states}
    a.dec_zero(start[machine.initial_state])                  # instruction 0: go to the initial state
    for q in states:
        # read: t := d // b, d := 0, and the remainder r = scanned cell is known
        exits = [a.fresh("read") for _ in range(b)]
        a.divide(D, T, b, start[q], exits)
        for r in range(b):
            s = symb.get(r, BLANK)
            rule = machine.table.get((q, s))
            a.here(exits[r])
            e1, e2, e3, e4 = (a.fresh() for _ in range(4))
            if rule is None:
                # halt: d = b*t + r is restored, then STOP
                a.dec_zero(e1)
                a.transfer(T, D, b, e1, e2)
                halt = a.fresh("halt")
                a.add(D, r, e2, halt)
                a.here(halt)
                a.stop()
                continue
            action, q2 = rule[2], rule[3]
            a.dec_zero(e1)
            if action == "R":
                # g := b*g + r (going through d, which is 0), then d := t
                a.transfer(G, D, b, e1, e2)
                a.add(D, r, e2, e3)
                a.transfer(D, G, 1, e3, e4)
                a.transfer(T, D, 1, e4, start[q2])
            elif action == "L":
                # d := b*t + r ; t := g // b ; g := t ; d := b*d + (remainder of g)
                e5 = a.fresh()
                a.transfer(T, D, b, e1, e2)
                a.add(D, r, e2, e3)
                rg = [a.fresh("g") for _ in range(b)]
                a.divide(G, T, b, e3, rg)
                for r2 in range(b):
                    f1, f2, f3, f4 = (a.fresh() for _ in range(4))
                    a.here(rg[r2])
                    a.dec_zero(f1)
                    a.transfer(T, G, 1, f1, f2)
                    a.transfer(D, T, b, f2, f3)
                    a.add(T, r2, f3, f4)
                    a.transfer(T, D, 1, f4, start[q2])
            else:
                # write: d := b*t + code(action)
                a.transfer(T, D, b, e1, e2)
                a.add(D, codes[action], e2, start[q2])
    return a.assemble(), codes, b

A counter machine has counters (natural numbers) and a numbered program:
    ("INC", r, j)      add 1 to counter r, go to instruction j;
    ("DEC", r, j, k)   if r > 0, subtract 1 and go to j; otherwise go to k;
    ("STOP",)          halt.

The translation is done in two stages (chapter "Other models"):

 1. Turing machine -> three counters g, d, t. The tape is seen as two numbers written
    in base b (b = number of symbols, the blank being the digit 0): d holds the scanned cell
    (units digit) and the cells to its right, g the cells to the left of the head (the nearest
    in the units). Reading the cell means computing the remainder of d by b; moving right means removing
    this digit from d and adding it to g; t is an auxiliary counter for multiplying and dividing by b.

class CounterMachine:
    def __init__(self, program, counters):
        self.program = program
        self.counters = list(counters)
        self._cycles = {}

    def __len__(self):
        return len(self.program)

    def _cycle(self, i):
        """If the instruction i = DEC(X, ...) begins a "simple" loop (following the successes:
        only DECs of the same counter X and INCs of other counters, back to i),
        returns (number of DECs per round, changes of the other counters, length of the round)."""
        if i in self._cycles:
            return self._cycles[i]
        X = self.program[i][1]
        j, ndec, delta, length, res = i, 0, {}, 0, None
        for _ in range(200):
            ins = self.program[j]
            length += 1
            if ins[0] == "DEC" and ins[1] == X:
                ndec += 1
                j = ins[2]
            elif ins[0] == "INC" and ins[1] != X:
                delta[ins[1]] = delta.get(ins[1], 0) + 1
                j = ins[2]
            else:
                break
            if j == i:
                res = (ndec, delta, length)
                break
        self._cycles[i] = res
        return res

    def run(self, values, max_real_steps=10**7, speed_up=True):
        """Returns (final values, number of steps of the machine, number of iterations of the interpreter)."""
        v = list(values)
        i, steps, iterations = 0, 0, 0
        while True:
            iterations += 1
            if iterations > max_real_steps:
                raise RuntimeError("too long")
            ins = self.program[i]
            if ins[0] == "STOP":
                return v, steps, iterations
            if ins[0] == "INC":
                v[ins[1]] += 1
                i = ins[2]
                steps += 1
                continue
            X = ins[1]
            if speed_up:
                cyc = self._cycle(i)
                if cyc is not None and v[X] >= cyc[0]:
                    rounds = v[X] // cyc[0]
                    v[X] -= rounds * cyc[0]
                    for r, dv in cyc[1].items():
                        v[r] += rounds * dv
                    steps += rounds * cyc[2]
                    continue
            if v[X] > 0:
                v[X] -= 1
                i = ins[2]
            else:
                i = ins[3]
            steps += 1


class Assembler:
    """Writes a program with labels: each instruction gets a number, jumps are resolved at the end."""

    def __init__(self):
        self.code, self.labels, self.n = [], {}, 0

    def fresh(self, prefix="e"):
        self.n += 1
        return "%s%d" % (prefix, self.n)

    def here(self, label):
        self.labels[label] = len(self.code)

    def inc(self, r, following):
        self.code.append(["INC", r, following])

    def dec(self, r, if_yes, if_no):
        self.code.append(["DEC", r, if_yes, if_no])

    def stop(self):
        self.code.append(["STOP"])

    def assemble(self):
        def res(x):
            return self.labels[x] if isinstance(x, str) else x
        prog = []
        for ins in self.code:
            if ins[0] == "INC":
                prog.append(("INC", ins[1], res(ins[2])))
            elif ins[0] == "DEC":
                prog.append(("DEC", ins[1], res(ins[2]), res(ins[3])))
            else:
                prog.append(("STOP",))
        return prog

    # ---- fragments: each begins at the given label and jumps to "end"
    def transfer(self, src, dst, factor, start, end):
        """dst += factor * src ; src := 0."""
        self.here(start)
        body = [self.fresh() for _ in range(factor)]
        self.dec(src, body[0] if factor else start, end)
        for k, e in enumerate(body):
            self.here(e)
            self.inc(dst, body[k + 1] if k + 1 < factor else start)

    def add(self, r, n, start, end):
        """r += n (n constant)."""
        if n == 0:
            self.here(start)
            self.dec_zero(end)
            return
        lab = [start] + [self.fresh() for _ in range(n - 1)] + [end]
        for k in range(n):
            self.here(lab[k])
            self.inc(r, lab[k + 1])

    def dec_zero(self, end):
        # "go to end": a jump is simulated by an instruction on a reserved counter, always zero
        self.dec(Z, end, end)

    def divide(self, src, quot, b, start, exits):
        """quot += src // b ; src := 0 ; jumps to exits[remainder]."""
        stages = [start] + [self.fresh() for _ in range(b)]
        for k in range(b):
            self.here(stages[k])
            self.dec(src, stages[k + 1], exits[k])
        self.here(stages[b])
        self.inc(quot, start)

def three_counters(machine):
    """Translates a Turing machine into a counter machine with counters g, d, t (plus Z, always zero).
    Returns (program, codes of the symbols, base b)."""
    codes = symbol_codes(machine)
    b = max(2, len(codes))
    symb = {c: s for s, c in codes.items()}
    a = Assembler()
    states = sorted(machine.states())
    start = {q: "read_" + q for q in states}
    a.dec_zero(start[machine.initial_state])                  # instruction 0: go to the initial state
    for q in states:
        # read: t := d // b, d := 0, and the remainder r = scanned cell is known
        exits = [a.fresh("read") for _ in range(b)]
        a.divide(D, T, b, start[q], exits)
        for r in range(b):
            s = symb.get(r, BLANK)
            rule = machine.table.get((q, s))
            a.here(exits[r])
            e1, e2, e3, e4 = (a.fresh() for _ in range(4))
            if rule is None:
                # halt: d = b*t + r is restored, then STOP
                a.dec_zero(e1)
                a.transfer(T, D, b, e1, e2)
                halt = a.fresh("halt")
                a.add(D, r, e2, halt)
                a.here(halt)
                a.stop()
                continue
            action, q2 = rule[2], rule[3]
            a.dec_zero(e1)
            if action == "R":
                # g := b*g + r (going through d, which is 0), then d := t
                a.transfer(G, D, b, e1, e2)
                a.add(D, r, e2, e3)
                a.transfer(D, G, 1, e3, e4)
                a.transfer(T, D, 1, e4, start[q2])
            elif action == "L":
                # d := b*t + r ; t := g // b ; g := t ; d := b*d + (remainder of g)
                e5 = a.fresh()
                a.transfer(T, D, b, e1, e2)
                a.add(D, r, e2, e3)
                rg = [a.fresh("g") for _ in range(b)]
                a.divide(G, T, b, e3, rg)
                for r2 in range(b):
                    f1, f2, f3, f4 = (a.fresh() for _ in range(4))
                    a.here(rg[r2])
                    a.dec_zero(f1)
                    a.transfer(T, G, 1, f1, f2)
                    a.transfer(D, T, b, f2, f3)
                    a.add(T, r2, f3, f4)
                    a.transfer(T, D, 1, f4, start[q2])
            else:
                # write: d := b*t + code(action)
                a.transfer(T, D, b, e1, e2)
                a.add(D, codes[action], e2, start[q2])
    return a.assemble(), codes, b

Pushdown automata

An automaton that has a single stack, of which it can read only the top element, cannot compute everything. With two stacks, it can: the two stacks play the role of the two halves of the tape of a Turing machine.

Automata with one stack (a finite automaton equipped with a stack) recognize exactly the context-free languages; they are not universal: for example the language $\{a^nb^nc^n:n\ge0\}$, obviously decidable, is recognized by no pushdown automaton. On the other hand, a finite automaton equipped with two stacks simulates a Turing machine.

In plain words. An automaton equipped with a single stack cannot compute everything. With two stacks, it can.

A stack is a memory of which only the top is visible, like a stack of plates. It suffices to check brackets, not to compare three quantities. Two stacks placed back to back form a Turing tape: what is to the left of the head is in the first stack, what is to the right in the second, and moving the head amounts to passing a plate from one stack to the other. The frontier of universality runs between “one” and “two”.

Two-stack automata. Such an automaton is given by a finite set of states $Q$, an initial state $q_0$, a stack alphabet $\Gamma$ and a partial table $\delta$ which, to a triple $(q,g,d)\in Q\times(\Gamma\cup\{\bot\})^2$ (the state and the tops of the stacks $G$ and $D$, $\bot$ denoting an empty stack), associates $(\pi_G,\pi_D,w_G,w_D,q')$: pop $G$ or not, pop $D$ or not (only if it is not empty), push the word $w_G$ onto $G$ and $w_D$ onto $D$, go to state $q'$. The automaton halts when $\delta$ is not defined.

Construction. Let $Z$ be a quadruple machine, with alphabet $\Gamma\ni B$. The automaton $A_Z$ has the states of $Z$ and, for each quadruple $q\,s\,a\,q'$, each $g\in\Gamma\cup\{\bot\}$ and each $d\in\{s\}$ (or $d\in\{B,\bot\}$ if $s=B$, an empty stack being read as a blank), the following transition $\delta(q,g,d)$, where $\pi_D$ means “pop $D$ if $d\ne\bot$”:

quadrupleaction on the stacks
$q\,s\,s'\,q'$ (write)$\pi_D$, push $s'$ onto $D$
$q\,s\,R\,q'$$\pi_D$, push $s$ onto $G$ (unless $s=B$ and $g=\bot$)
$q\,s\,L\,q'$pop $G$ if $g\ne\bot$; $\pi_D$; push onto $D$ the word $s\,\hat g$, where $\hat g=g$ if $g\ne\bot$ and $\hat g=B$ otherwise (the $s$ is omitted if $s=B$ and $d=\bot$)

Invariant. Say that $(q,G,D)$ represents the configuration of $Z$ with state $q$, tape $\tau$ and head at $p$ if, read from the top and completed with blanks, $D$ is the sequence $\tau(p),\tau(p+1),\dots$ and $G$ the sequence $\tau(p-1),\tau(p-2),\dots$. The initial configuration of $Z$ is represented by $(q_0,\varnothing,D_0)$, where $D_0$ contains the tape, cell $0$ at the top. Suppose that $(q,G,D)$ represents $(q,\tau,p)$. The top of $D$ is $\tau(p)$, or $\bot$ if $\tau(p)=B$ and $D$ is empty; so $\delta(q,g,d)$ is defined if and only if $Z$ has a quadruple beginning with $q\,\tau(p)$, and both halt together. Otherwise, one checks case by case that the result represents the next configuration: writing replaces the top of $D$; moving right passes $\tau(p)$ from the top of $D$ to the top of $G$, and the new top of $D$ is $\tau(p+1)$; moving left brings $\tau(p-1)$ (the top of $G$, or a blank) above $\tau(p)$ on $D$. By induction, the automaton makes one step for each step of $Z$, and halts with the same tape. It has at most $2(|\Gamma|+1)$ transitions per quadruple.

One stack is not enough. A one-stack automaton that reads its input from left to right recognizes exactly the context-free languages (proof), and the pumping lemma shows that $\{a^nb^nc^n\}$ is not one of them. With two stacks, one first copies the input onto $D$, then simulates a Turing machine that decides this language. Problems about pushdown automata remain partly decidable (emptiness of a context-free language is, proposition), but the equivalence of two nondeterministic pushdown automata is undecidable.

    for each step of the machine. The blank is never pushed needlessly: an empty stack stands for blanks."""
    tops = sorted(machine.symbols()) + [EMPTY]
    trans = {}
    for (q, s, action, q2) in machine.quadruples:
        read_d = [s, EMPTY] if s == BLANK else [s]        # on D, a blank may be an empty stack
        for d in read_d:
            pops_d = d != EMPTY
            for g in tops:
                if action == "R":
                    # the scanned cell goes onto G; the next cell becomes the top of D
                    push_g = () if (s == BLANK and g == EMPTY) else (s,)

                elif action == "L":

                    push_d = ((s,) if pops_d or s != BLANK else ()) + (g if g != EMPTY else BLANK,)
                    trans[(q, g, d)] = (g != EMPTY, pops_d, (), push_d, q2)
                else:
                    # writing: the top of D is replaced
                    trans[(q, g, d)] = (False, pops_d, (), (action,), q2)
    return TwoStackAutomaton(trans, machine.initial_state)

"""stacks.py: two-stack automata, and the translation of a Turing machine into a two-stack automaton.

A two-stack automaton has a finite set of states and two stacks G (left) and D (right).
At each step, it looks at its state and at the tops of the two stacks (EMPTY if a stack is empty),
then it may pop each of the two stacks, push a word on each, and change state.
If it has no transition for what it sees, it halts.

Simulating a tape (chapter "Other models"): the stack D holds the scanned cell (on top)
and all the cells to its right; the stack G holds the cells to the left of the head, the nearest
on top. An empty stack reads as infinitely many blanks.

    python3 stacks.py                    # translates addition and compares the two runs
    python3 stacks.py examples/addition.tm 2 3 --trace

import sys

from machines import Machine, BLANK, STROKE, initial_tape

EMPTY = "⊥"


class TwoStackAutomaton:
    """Transitions: (state, top of G, top of D) -> (pop G, pop D, word pushed on G,
    word pushed on D, new state). The pushed words are tuples, the last element on top."""

    def __init__(self, transitions, initial_state):
        self.transitions = dict(transitions)
        self.initial_state = initial_state

    def __len__(self):
        return len(self.transitions)

    def step(self, state, G, D):
        """Performs one step (G and D are lists, top at the end). Returns the new state, or None when halted."""
        key = (state, G[-1] if G else EMPTY, D[-1] if D else EMPTY)
        t = self.transitions.get(key)
        if t is None:
            return None
        pop_g, pop_d, push_g, push_d, following = t
        if pop_g:
            G.pop()
        if pop_d:
            D.pop()
        G.extend(push_g)
        D.extend(push_d)
        return following

    def run(self, G, D, max_steps=10**7, trace=None):
        state, n = self.initial_state, 0
        while True:
            if trace:
                trace(state, G, D)
            new = self.step(state, G, D)
            if new is None:
                return state, G, D, n
            state, n = new, n + 1
            if n >= max_steps:
                raise RuntimeError("no halt after %d steps" % n)


def from_turing(machine):
    """Translates a quadruple Turing machine into a two-stack automaton that makes one step
    for each step of the machine. The blank is never pushed needlessly: an empty stack stands for blanks."""
    tops = sorted(machine.symbols()) + [EMPTY]
    trans = {}
    for (q, s, action, q2) in machine.quadruples:
        read_d = [s, EMPTY] if s == BLANK else [s]        # on D, a blank may be an empty stack
        for d in read_d:
            pops_d = d != EMPTY
            for g in tops:
                if action == "R":
                    # the scanned cell goes onto G; the next cell becomes the top of D
                    push_g = () if (s == BLANK and g == EMPTY) else (s,)
                    trans[(q, g, d)] = (False, pops_d, push_g, (), q2)
                elif action == "L":
                    # the top of G (or a blank) comes back onto D, above the scanned cell
                    push_d = ((s,) if pops_d or s != BLANK else ()) + (g if g != EMPTY else BLANK,)
                    trans[(q, g, d)] = (g != EMPTY, pops_d, (), push_d, q2)
                else:
                    # writing: the top of D is replaced
                    trans[(q, g, d)] = (False, pops_d, (), (action,), q2)
    return TwoStackAutomaton(trans, machine.initial_state)


def initial_stacks(*args):
    """The initial tape q0 1^{x1+1} B ...: G empty, D holds the tape, the first cell on top."""
    tape = initial_tape(args)
    n = max(tape) + 1 if tape else 0
    return [], [tape.get(i, BLANK) for i in reversed(range(n))]


def tape_from_stacks(G, D):
    """Rebuilds (dictionary of the non-blank cells, head position = 0)."""
    tape = {}
    for i, s in enumerate(reversed(D)):
        if s != BLANK:
            tape[i] = s
    for i, s in enumerate(reversed(G)):
        if s != BLANK:
            tape[-1 - i] = s
    return tape


def compare(machine, *args, max_steps=10**6):
    """Runs the machine and the automaton side by side and checks, step by step, that the tape and the state
    are the same. Returns (number of steps, number of strokes)."""
    auto = from_turing(machine)
    c = machine.initial_configuration(*args)
    G, D = initial_stacks(*args)
    state = auto.initial_state
    while True:
        tape = {i - c.position: s for i, s in c.tape.items() if s != BLANK}
        assert tape == tape_from_stacks(G, D), "different tapes at step %d" % c.steps
        assert state == c.state
        machine_goes_on = machine.step(c)
        new = auto.step(state, G, D)
        assert (new is None) == (not machine_goes_on), "different halts at step %d" % c.steps
        if new is None:
            return c.steps, c.number_of_strokes()
        state = new
        if c.steps > max_steps:
            raise RuntimeError("too long")

Post’s correspondence problem

Post’s game of dominoes, already met in the chapter Languages, can imitate any computation; this is why one cannot decide whether it has a solution.

Theorem
Undecidability of Post’s correspondence problem (1946)

An instance is a finite list of dominoes $\frac{u_1}{v_1},\dots,\frac{u_k}{v_k}$, where the $u_i,v_i$ are words. A solution is a nonempty sequence of indices $i_1,\dots,i_m$ (repetitions allowed) such that $u_{i_1}\cdots u_{i_m}=v_{i_1}\cdots v_{i_m}$. There is no algorithm that decides whether an instance has a solution.

In plain words. We have a set of dominoes, each bearing a word on top and a word at the bottom. One cannot decide in general whether they can be lined up (reusing each domino as often as one likes) so as to read the same word on top and at the bottom.

A game a child understands, and no program can say in general whether it has a solution. This game, invented by Post in 1946, is the favourite tool for showing that questions about grammars and languages are undecidable, because it speaks only of words. It is also used for matrix products. The simulator on the page makes it possible to look for solutions and to see that they can be very long.

The complete proof is given in the chapter Languages and grammars: one reduces the word problem of a semi-Thue system, itself undecidable by a reduction from halting, to the modified Post problem (whose solution must start with a prescribed domino), then the latter to Post’s problem. The dominoes are designed so that the only way to make top and bottom equal is to write, on top, the sequence of words of a derivation, the bottom always being one word ahead; catching up is possible only if the derivation reaches the target word. The problem is semi-decidable (try all sequences by increasing length), hence $\Sigma_1$-complete. It is decidable for two dominoes, undecidable from five on (Neary, 2015).

Example: dominoes $\frac{a}{baa}$, $\frac{ab}{aa}$, $\frac{bba}{bb}$. The sequence $3,2,3,1$ gives on top $bba\cdot ab\cdot bba\cdot a=bbaabbbaa$ and on the bottom $bb\cdot aa\cdot bb\cdot baa=bbaabbbaa$: it is a solution.

Theorem
From Turing machines to Post’s dominoes

To every (quadruple) machine $Z$ and every input $\vec x$, one effectively associates a list of dominoes $\mathcal D_{Z,\vec x}$ that has a solution if and only if $Z$ halts on $\vec x$. Consequently Post’s problem is undecidable, and even $\Sigma_1$-complete.

In plain words. For any program, one can build a set of dominoes that has a solution exactly when the program halts. The solution, when it exists, writes out the whole computation of the program, step after step.

The dominoes are designed so that there is no choice. The first domino writes at the bottom the starting state of the machine. To catch up with the bottom, it must be copied on top, and the only dominoes that allow this write at the bottom, at the same time, the next step of the computation. The bottom therefore always keeps one step ahead: it is like copying a page while always having the next line to write underneath.

The top can catch up with the bottom only at the very end: special dominoes, which are of use only once the machine has halted, “eat” the tape one cell at a time until the two lines have the same length. If the machine never halts, these dominoes are never used, and the bottom keeps its lead forever: there is no solution. Knowing whether a set of dominoes has a solution would therefore be knowing whether a program halts.

The words are written over the alphabet formed by the symbols $\Gamma$ of $Z$, its states, a separator $\#$ and a letter $H$ (“halted”). A configuration with state $q$ and the head on the cell containing $s$ is written $u\,q\,s\,v$ ($u$ and $v$ words of $\Gamma$, possibly surrounded by blanks). We first build a modified list, whose solution must begin with the first domino (a domino is written $\frac{\text{top}}{\text{bottom}}$):

  1. start: $\frac{\#}{\#\,B\,q_0\,w\,\#}$, where $q_0w$ is the initial configuration (the blank added in front is harmless);
  2. copy: $\frac{a}{a}$ for $a\in\Gamma$; separators: $\frac{\#}{\#}$ and $\frac{\#}{B\,\#}$ (add a blank to the right of the configuration being written);
  3. for each quadruple: $q\,s\,s'\,q'$ gives $\frac{q\,s}{q'\,s'}$; $q\,s\,R\,q'$ gives $\frac{q\,s}{s\,q'}$; $q\,s\,L\,q'$ gives $\frac{c\,q\,s}{q'\,c\,s}$ for each $c\in\Gamma$, and, at the left edge, $\frac{\#\,q\,s}{\#\,q'\,B\,s}$ and $\frac{\#\,q\,s}{B\,\#\,q'\,B\,s}$;
  4. halt: $\frac{q\,s}{H\,s}$ for each pair $(q,s)$ that begins no quadruple;
  5. erasure: $\frac{a\,H}{H}$ and $\frac{H\,a}{H}$ for $a\in\Gamma$; end: $\frac{H\,\#\,\#}{\#}$.

If $Z$ halts, there is a solution. Let $C_0,C_1,\dots,C_n$ be the computation, $C_n$ a halting configuration. We write the word $\#C_0\#C_1\#\cdots\#C_n\#C'_n\#E_1\#\cdots\#E_m\#H\#\#$, where $C'_n$ is $C_n$ with its state replaced by $H$, and where each $E_{j+1}$ is obtained by erasing a letter next to $H$ in $E_j$, down to $H$ alone. Each configuration is completed with the necessary blanks (a blank on the right when the head reaches the end, on the left when it must go there). This word is obtained on top and at the bottom with the same sequence of dominoes: the start domino, then, for each configuration on top, copies and a rule, halt or erasure domino which write at the bottom the next configuration, separated by a separator domino; finally $\frac{\#}{\#}$ and the end domino.

If there is a solution, $Z$ halts. Consider a solution, which begins with the start domino, and follow the simultaneous reading of top and bottom. We show by induction that, each time the top has written $\#C_0\#\cdots\#C_k$ (with configurations possibly completed with blanks), the bottom has written exactly $\#C_0\#\cdots\#C_k\#C_{k+1}$, where $C_{k+1}$ follows $C_k$ in the computation of $Z$, or else $C_k$ contains $H$. The top must copy $C_k$, which contains a single state letter, preceded by letters of $\Gamma$ (or by $\#$) and followed by a letter of $\Gamma$ (otherwise no domino fits). Letters of $\Gamma$ can be covered only by copies; the state letter $q$, with the letter $s$ that follows it, can be covered only by the domino of the quadruple beginning with $q\,s$ (there is at most one, since $Z$ is deterministic), or by a halt domino if this quadruple does not exist. The bottom therefore receives the next configuration. Now, in all dominoes except the erasures and the end domino, the bottom is at least as long as the top: as long as no $H$ appears, the bottom keeps at least one configuration ahead, and the solution cannot end. An $H$ appears at the bottom only through a halt domino, when the top copies a halting configuration of $Z$: the machine halts.

Ordinary list. The star trick (step 2 of the proof in the chapter Languages) transforms the modified list into an ordinary list that has a solution if and only if the modified list has one beginning with the first domino. The problem is semi-decidable (one tries all sequences by increasing length), hence $\Sigma_1$-complete by the completeness of halting.

def solution_from_computation(machine, dominoes, names, *args, max_steps=10**5):
    """Builds the solution of the modified problem from the computation of the machine (which must halt).
    We write the successive rows (the configurations); each top row is copied to the bottom
    while being turned into the next row, the bottom always being one row ahead."""
    index = {}
    for i, (h, b) in enumerate(dominoes):
        index.setdefault((tuple(h), tuple(b)), i)

    def ind(h, b):
        return index[(tuple(h), tuple(b))]

    def copy(words):
        return [ind([c], [c]) for c in words]

    tape = initial_tape(args)
    right = [tape.get(i, BLANK) for i in range(max(tape) + 1)] if tape else [BLANK]
    left, q = [BLANK], machine.initial_state
    sol = [0]
    pad = False                 # must a blank be added on the right of the next row?
    first_row, steps = True, 0
    while True:
        s = right[0]
        rule = machine.table.get((q, s))
        left_edge = rule is not None and rule[2] == "L" and not left
        # the top separator before this row writes, at the bottom, the end of the next row
        if not first_row and not left_edge:
            sol.append(ind([SEP], ([BLANK] if pad else []) + [SEP]))
        if rule is None:                                          # the machine halts
            sol += copy(left) + [ind([q, s], [HALT, s])] + copy(right[1:])
            break
        act, q2 = rule[2], rule[3]
        old_pad, pad = pad, False
        if act == "R":
            sol += copy(left) + [ind([q, s], [s, q2])] + copy(right[1:])
            left, right = left + [s], right[1:]
            if not right:
                right, pad = [BLANK], True
        elif act == "L" and left_edge:
            sol.append(ind([SEP, q, s], ([BLANK] if old_pad else []) + [SEP, q2, BLANK, s]))
            sol += copy(right[1:])
            right = [BLANK] + right
        elif act == "L":
            c = left[-1]
            sol += copy(left[:-1]) + [ind([c, q, s], [q2, c, s])] + copy(right[1:])
            left, right = left[:-1], [c] + right
        else:
            sol += copy(left) + [ind([q, s], [q2, act])] + copy(right[1:])
            right = [act] + right[1:]
        q, first_row, steps = q2, False, steps + 1
        if steps > max_steps:
            raise RuntimeError("too long")
    # the bottom row now contains H; one letter is erased per row
    row = left + [HALT] + right
    while len(row) > 1:
        sol.append(ind([SEP], ([BLANK] if pad else []) + [SEP]))
        if pad:
            row = row + [BLANK]
            pad = False
        k = row.index(HALT)
        if k > 0:
            sol += copy(row[:k - 1]) + [ind([row[k - 1], HALT], [HALT])] + copy(row[k + 1:])
            row = row[:k - 1] + row[k:]
        else:
            sol += [ind([HALT, row[1]], [HALT])] + copy(row[2:])
            row = [HALT] + row[2:]
    sol.append(ind([SEP], [SEP]))
    sol.append(ind([HALT, SEP, SEP], [SEP]))
    return sol

"""post.py: the Post correspondence problem, and the translation of a Turing machine into dominoes.

A domino is a pair (top, bottom) of words; here a word is a tuple of "letters", each letter
being a string (a tape symbol, a state name, the separator #...). A solution of a list
of dominoes is a sequence of indices such that the concatenation of the tops equals that of the bottoms.

Construction (chapter "Other models"): for a machine Z and an input x, we build
 1. a "modified" list of dominoes, whose solution must begin with the first domino;
    it has a solution if and only if Z halts on x: the only way to make the top and the
    bottom equal is to write the sequence of configurations of the computation, separated by #, the bottom always
    being one configuration ahead;
 2. an ordinary list of dominoes, by the star trick of the chapter "Languages".

    python3 post.py                         # dominoes for the addition 1 + 1, solution checked
    python3 post.py examples/successor.tm 0 --dominoes
    python3 post.py --search                # breadth-first search on small examples

"""

# --------------------------------------------------------------------------- solutions
def concatenate(dominoes, indices):
    top, bottom = [], []
    for i in indices:
        top.extend(dominoes[i][0])
        bottom.extend(dominoes[i][1])
    return tuple(top), tuple(bottom)


def is_solution(dominoes, indices, first=None):
    if not indices or (first is not None and indices[0] != first):
        return False
    h, b = concatenate(dominoes, indices)
    return h == b


def search(dominoes, max_nodes=200000, first=None):
    """Breadth-first search for a solution. Only the "lead" of one side over the other is kept:
    two sequences that leave the same lead have the same extensions. Returns a solution
    (list of indices) or None if nothing is found within the limit: this is a semi-decision."""
    start = [first] if first is not None else range(len(dominoes))
    queue, seen = deque(), set()

    def lead(h, b):
        n = min(len(h), len(b))
        if h[:n] != b[:n]:
            return None
        return ("t", h[n:]) if len(h) > n else ("b", b[n:])

    for i in start:
        a = lead(*dominoes[i])
        if a is not None:
            if a[1] == ():
                return [i]
            queue.append((a, [i]))
            seen.add(a)
    while queue and len(seen) < max_nodes:
        (side, rest), seq = queue.popleft()
        for i, (h, b) in enumerate(dominoes):
            if side == "t":
                a = lead(rest + h, b)
            else:
                a = lead(h, rest + b)
            if a is None:
                continue
            if a[1] == ():
                return seq + [i]
            if a not in seen:
                seen.add(a)
                queue.append((a, seq + [i]))
    return None

            row = row[:k - 1] + row[k:]
        else:
            sol += [ind([HALT, row[1]], [HALT])] + copy(row[2:])
            row = [HALT] + row[2:]
    sol.append(ind([SEP], [SEP]))
    sol.append(ind([HALT, SEP, SEP], [SEP]))
    return sol


def to_ordinary(dominoes):
    """Star trick (chapter "Languages"): the first domino becomes the only one that can begin."""
    def left(w):
        r = []
        for c in w:
            r += [STAR, c]
        return r

    def right(w):
        r = []
        for c in w:
            r += [c, STAR]
        return r
    new = [(tuple(left(dominoes[0][0])), tuple([STAR] + right(dominoes[0][1])))]
    for h, b in dominoes:
        new.append((tuple(left(h)), tuple(right(b))))
    new.append(((STAR, END), (END,)))
    return new


def ordinary_solution(modified_sol, nb_dominoes):
    """A solution 0, i2, ..., ir of the modified problem gives the solution 0, i2+1, ..., ir+1, end."""
    return [0] + [i + 1 for i in modified_sol[1:]] + [nb_dominoes + 1]


def show_word(w, max_letters=60):
    t = " ".join(w)
    return t if len(w) <= max_letters else " ".join(w[:max_letters]) + " …"

Multiplicative systems: FRACTRAN

John Conway invented a language whose programs are lists of fractions. One starts from a number, multiplies it by the first fraction of the list that gives an integer result, and starts again. This primary-school game suffices to compute everything.

Theorem
Universality of FRACTRAN (Conway, 1987)

A FRACTRAN program is a finite list of fractions $f_1,\dots,f_k$. Starting from an integer $n$, find the first fraction $f_i$ such that $n f_i$ is an integer, replace $n$ by $nf_i$, and start again; stop if none works. This model is universal: for every computable function $f$, there is a program and a prime $q$ such that, starting from $q\,2^x$, the program halts if and only if $f(x)$ is defined, and then on $3^{f(x)}$.

In plain words. A FRACTRAN program is a simple list of fractions. One starts from an integer; one multiplies it by the first fraction of the list that still gives an integer result; and one starts again. This strange language can compute everything that is computable.

Computing, here, is multiplying, and nothing else. The secret is prime factorization: a number such as 23 × 35 × 7 contains three “counters” (the exponents 3, 5 and 1), and multiplying by a fraction adds or removes units from these counters. We are back to counter machines. The mathematician John Conway even wrote a program of fourteen fractions that produces, one after another, all the prime numbers.

Let $f$ be a computable function and $M$ a counter machine that computes it in the sense of step 1 of Minsky’s theorem (input in $r_1$; on halting, result in $r_0$ and other counters zero, emptying them if necessary). We also assume that no instruction jumps to itself: if needed, such an instruction $i$ is replaced by a detour through two new instructions, $\mathrm{INC}(t,i^*)$ and $i^*:\mathrm{DEC}(t,i,i)$, on an unused counter $t$.

Associate a prime $p_r$ with each counter $r_r$, with $p_1=2$ and $p_0=3$ (here the index is that of the counter, not the rank of the prime), and a prime $q_i$ with each instruction, all distinct. The configuration “instruction $i$, counters $c_r$” is coded by $n=q_i\prod_rp_r^{c_r}$. The FRACTRAN program contains, for each instruction $i$:

  • if $i$ is $\mathrm{INC}(r,j)$: the fraction $\dfrac{q_jp_r}{q_i}$;
  • if $i$ is $\mathrm{DEC}(r,j,k)$: the fraction $\dfrac{q_j}{q_ip_r}$, then, further down the list, $\dfrac{q_k}{q_i}$;
  • if $i$ is the halt: the fraction $\dfrac1{q_i}$.

Since $j,k\ne i$, these fractions are in lowest terms, and $nf$ is an integer if and only if the denominator of $f$ divides $n$. If $n$ codes a configuration with instruction $i$, only $q_i$ among the $q$ divides $n$, so only the fractions of instruction $i$ apply: for $\mathrm{INC}$, $n$ becomes the code of the next configuration; for $\mathrm{DEC}$, the first fraction applies if and only if $p_r$ divides $n$, that is, $c_r>0$, and gives $q_j\cdot n/(q_ip_r)$; otherwise the second gives $q_k\cdot n/q_i$. On halting, $n$ becomes $\prod_rp_r^{c_r}=3^{f(x)}$, which no fraction can multiply any more (every denominator contains a $q$). Thus, starting from $q_1\,2^x$, the program halts if and only if $f(x)$ is defined, and then on $3^{f(x)}$.

Conversely, a function computed in this way by a FRACTRAN program is computable, since each step is an elementary arithmetic computation.

The one-fraction program $\left(\frac{3}{2}\right)$ computes addition: starting from $2^a3^b$, it halts on $3^{a+b}$.

Cellular automata

A cellular automaton is a row of cells, each black or white, which all change at the same time according to the colour of their neighbours. Conway’s famous “Game of Life” is a two-dimensional example. Even rule 110, one of the simplest in one dimension, can compute everything.

Definition
Cellular automata, elementary automata

A one-dimensional cellular automaton is given by a finite set of states $Q$, a radius $r\ge1$ and a local rule $f:Q^{2r+1}\to Q$. A configuration is a sequence $c\in Q^{\mathbb Z}$ (an infinite line of cells); in one step, all cells change at the same time, according to $c'_i=f(c_{i-r},\dots,c_{i+r})$. The elementary automata are those of radius $1$ on $Q=\{0,1\}$. Their rule is given by the eight values $f(1,1,1),f(1,1,0),\dots,f(0,0,0)$, read as the binary expansion of an integer between $0$ and $255$, the Wolfram number of the rule. Thus rule 110, $110=01101110$ in binary, is:

$$\begin{array}{cccccccc}111&110&101&100&011&010&001&000\\\downarrow&\downarrow&\downarrow&\downarrow&\downarrow&\downarrow&\downarrow&\downarrow\\0&1&1&0&1&1&1&0\end{array}$$

In plain words. A cellular automaton is a row of cells, white or black for example. At each instant, all cells change at the same time, and each chooses its new colour by looking only at its own colour and that of its neighbours.

This is the model of computation closest to physics: no reading head, no conductor, only a local rule applied everywhere at once, like the laws of nature. John von Neumann and Stanisław Ulam invented it around 1950 to study machines capable of reproducing themselves. By drawing the successive rows one below the other, one obtains a picture of the whole history of the computation, the same big table that serves for tilings and for logic.

The simulator above draws $100$ steps on a line of $160$ cells closed into a ring. A few rules to try: $110$ (localized structures that move and interact), $90$ (the Sierpinski triangle, see the exercise), $30$ (random-looking behaviour), $184$ (a model of road traffic), $240$ (a simple shift).

Theorem
A cellular automaton simulates a Turing machine in real time

For every Turing machine $Z$, there is a cellular automaton of radius $1$ each of whose steps performs one step of $Z$. Consequently, the question “starting from this finite configuration (surrounded by blank cells), will the automaton make such-and-such a state appear?” is undecidable for some automata. Conversely, the evolution of a cellular automaton from a finite configuration can be computed by a Turing machine.

In plain words. A cellular automaton can imitate a Turing machine, at the rate of one step of the machine for one step of the automaton. Conversely, a Turing machine can compute the evolution of a cellular automaton.

It suffices that each cell of the automaton represent a cell of the tape, with in addition a mark “the head is here, at such and such a stage”. The marked cell and its neighbours are updated according to the program of the machine, the others do not move. The two models therefore compute exactly the same things. The automaton can only be faster for some tasks, since all its cells work together.

Take as states of the automaton the symbols $s$ of $Z$ and the pairs $(q,s)$ (“the head, in state $q$, is on this cell, which contains $s$”). The initial configuration carries $(q_0,\text{blank})$ in one cell and blanks elsewhere. The local rule $f(g,c,d)$ is as follows. If $c=(q,s)$ and $Z$ has the transition “write $s'$, go to state $q'$, move”, then the new value is $s'$ (the head leaves); if $q$ is a halting state, the cell keeps the value $(q,s)$. If $c=s$ is a symbol and the left neighbour $g=(q,t)$ has a rightward transition with target state $q'$, the new value is $(q',s)$ (the head arrives); likewise with the right neighbour for a leftward transition. Otherwise $c$ does not change. Since there is only one head, these cases do not overlap, and the configuration at time $t$ is exactly that of $Z$ after $t$ steps. The state $(q_{\text{halt}},s)$ appears if and only if $Z$ halts: conclude by the undecidability of halting. For the converse, a finite configuration stays finite (it grows by at most $r$ cells on each side at each step), and the rule is applied cell by cell.

The program automates.py builds this local rule for a 3-state Radó machine, and checks that the automaton and the machine have the same configuration after each of the first 20 steps; the machine halts at step 14 with six symbols $1$, the value of Σ(3).

Theorem
Rule 110 is universal (Cook, 2004)

The elementary automaton 110 is universal: for every Turing machine and every input, there is a configuration of rule 110, made of a finite pattern placed on a periodic background, whose evolution simulates the computation of the machine. (Result quoted for information, conjectured by Wolfram in 1985 and proved by Matthew Cook, whose proof was published in 2004.)

In plain words. In “rule 110”, each cell is white or black and looks only at its two immediate neighbours. This tiny rule can nevertheless compute everything.

Two colours, three cells looked at, eight possible situations: it is hard to imagine anything simpler. The physicist Stephen Wolfram suspected it in 1985, and Matthew Cook proved it in 2004. In the pictures produced by this rule, one sees patterns that move like little spaceships on a regular background and collide. Cook showed that by arranging these spaceships well, their collisions reproduce a computation.

Rule 110 joins the list of systems that can compute everything with almost nothing: two counters, a list of fractions, equations in integers, the famous Game of Life. As with them, this power has a downside: simple questions about its evolution have no computable answer.

Two clarifications, quoted for information. First, the initial configuration is not finite in the sense of the previous theorem: an infinite periodic background is needed, and even a periodic repetition of one pattern on the right and another on the left; it is a computable configuration, but not one with finite support. Second, Cook’s simulation was exponentially slow; Neary and Woods (2006) made it polynomial, which shows that predicting the evolution of rule 110 is a $\mathsf P$-complete problem. Rule 110 has also been used to build very small universal Turing machines.

Remark
Wolfram’s classification and undecidability in automata

Results quoted for information.

  • Wolfram’s classification (1984). Wolfram classified automata, according to their observed behaviour from random configurations, into four classes: (I) evolution towards a homogeneous configuration; (II) stable or periodic structures; (III) chaotic, random-looking behaviour (rule 30); (IV) complex localized structures that interact (rule 110, Game of Life). He conjectured that class IV automata are capable of universal computation. This classification is empirical: once formalized, membership of an automaton in a class is undecidable (Culik and Yu, 1988). See the references of Wolfram and of Culik and Yu in the bibliography.
  • Global properties. Whether a one-dimensional automaton is reversible (its global function is bijective) is decidable (Amoroso and Patt, 1972), but it is undecidable in dimension 2 (Kari, 1990). Whether every configuration eventually becomes uniform (nilpotency) is undecidable already in dimension 1 (Kari, 1992).
  • Gardens of Eden. A configuration is a Garden of Eden if it has no predecessor: it can only occur at the start. By the Moore-Myhill theorem (1962–1963), an automaton has Gardens of Eden if and only if there are two distinct configurations, differing on only finitely many cells, that have the same image. The Game of Life has Gardens of Eden. Their existence is decidable in dimension 1 and undecidable in dimension 2 (Kari).

In plain words. Wolfram sorted cellular automata into four families according to what one observes: those that become uniform, those that repeat, those that look chaotic, and those that produce complex structures. Knowing which family a given automaton belongs to is undecidable in general.

The classification is very telling when one looks at the pictures, but it is not a precise definition: it describes what one sees by trying a few random starts. The automata of the fourth family, those that look like life, are precisely the ones that can compute, and for them one cannot predict for certain what will eventually happen.

★Exercise 1 — Adding with counters

Write a counter machine program that adds the contents of register 2 to register 1 (and empties register 2).

Solution

Instruction 0: $\mathrm{DEC}(2,1,2)$; instruction 1: $\mathrm{INC}(1,0)$. There is no instruction 2: going there halts the machine. As long as register 2 is nonzero, it is decremented and register 1 is incremented; when it is empty, $\mathrm{DEC}$ sends to instruction 2 and the machine halts with $r_1+r_2$ in register 1. The program takes $2r_2+1$ steps.

★★Exercise 2 — Multiplying with counters

Write a program that puts $r_1\times r_2$ in register 3, starting from $r_3=r_4=0$. Register 4 may be used as auxiliary memory to restore $r_2$.

Solution
$$\begin{aligned} &0:\ \mathrm{DEC}(1,1,9) &&1:\ \mathrm{DEC}(2,2,4) &&2:\ \mathrm{INC}(3,3)\\ &3:\ \mathrm{INC}(4,1) &&4:\ \mathrm{DEC}(4,5,0) &&5:\ \mathrm{INC}(2,4) \end{aligned}$$

For each unit removed from $r_1$ (instruction 0), the loop 1-2-3 transfers $r_2$ into $r_4$ while adding as much to $r_3$; then the loop 4-5 puts $r_4$ back into $r_2$ and returns to 0. When $r_1$ is empty, instruction 0 sends to 9, which does not exist: halt, with $r_3=r_1r_2$ and $r_2$ intact. A simulation on $r_1,r_2\in\{0,\dots,3\}$ confirms it. The number of steps is of the order of $4r_1r_2$: counter machines compute everything, but slowly, since they only know unary.

★★★Exercise 3 — A FRACTRAN program for multiplication

Show that the FRACTRAN program $\frac{455}{33},\frac{11}{13},\frac1{11},\frac37,\frac{11}2,\frac13$, started on $2^a3^b$, halts on $5^{ab}$.

Solution

Read an integer $2^{r_2}3^{r_3}5^{r_5}7^{r_7}11^{r_{11}}13^{r_{13}}$ as a register state, the small primes $7$, $11$, $13$ playing the role of control states. Multiplying by $\frac{455}{33}=\frac{5\cdot7\cdot13}{3\cdot11}$ requires $r_3\ge1$ and $r_{11}\ge1$: it removes 1 from $r_3$, adds 1 to $r_5$ and $r_7$, and moves from state 11 to state 13. Then $\frac{11}{13}$ returns to state 11. As long as $r_{11}=1$ and $r_3>0$, these two fractions alternate: they transfer $r_3$ to $r_5$ (the product) and to $r_7$ (a copy). When $r_3=0$, $\frac1{11}$ leaves state 11; then $\frac37$ (the first applicable fraction) copies $r_7$ back into $r_3$. When $r_7=0$, $\frac{11}2$ removes 1 from $r_2$ and restarts state 11. Thus each unit of $r_2=a$ adds $r_3=b$ to $r_5$. When $r_2=0$, only $\frac13$ still applies and empties $r_3$. What remains is $5^{ab}$. The simulation on $a,b\le3$ does give $5^{ab}$. The order of the fractions is essential: it is what codes the tests.

★Exercise 4 — Running rule 110 by hand

Starting from a single black cell ($\cdots000\,1\,000\cdots$), compute the next three lines of rule 110. In which direction does the pattern grow?

Solution

Only the cells whose neighbourhood contains the $1$ can change. The cell to the left of the $1$ sees $001\mapsto1$, the cell of the $1$ sees $010\mapsto1$, the one on the right sees $100\mapsto0$. Line 1: $11$ (the initial cell and its left neighbour). Line 2: $111$. Line 3: $1101$. The pattern grows to the left, one cell per step, and stays bounded on the right by the starting cell; the simulator in the text, started with “one cell on the right”, shows what follows. The program automates.py prints the first eight lines.

★Exercise 5 — Wolfram numbers

What is the Wolfram number of the rule “each cell takes the value of its left neighbour”? And of the rule “each cell takes the exclusive or of its two neighbours”? How many elementary automata are there?

Solution

For the first, the new value is the first bit of the neighbourhood: $111,110,101,100\mapsto1$, the others $\mapsto0$, that is, $11110000$ in binary, $240$. The pattern shifts one cell to the right at each step. For the second, $f(g,c,d)=g\oplus d$ equals $1$ for $110,100,011,001$: $01011010$, that is, $90$. There are $2^8=256$ elementary automata, one for each function from $\{0,1\}^3$ to $\{0,1\}$.

★★Exercise 6 — Rule 90 and Pascal’s triangle

Show that, starting from a single black cell at position $0$, cell $j$ at time $t$ equals the binomial coefficient $\binom{t}{(t+j)/2}$ modulo $2$ if $t+j$ is even and $|j|\le t$, and $0$ otherwise. What figure is obtained?

Solution

By induction on $t$. At time $0$, only cell $0$ equals $1=\binom00$. Assume the formula holds at time $t$; rule 90 gives $c_{t+1}(j)=c_t(j-1)\oplus c_t(j+1)$. If $t+1+j$ is odd, so are $t+(j-1)$ and $t+(j+1)$, both terms are zero, and $c_{t+1}(j)=0$. Otherwise, set $k=(t+1+j)/2$: then $c_t(j-1)\equiv\binom t{k-1}$ and $c_t(j+1)\equiv\binom tk$ modulo $2$ (with the convention $\binom tk=0$ outside $0\le k\le t$), and the exclusive or is the sum modulo $2$. Pascal’s rule $\binom t{k-1}+\binom tk=\binom{t+1}k$ gives the result. One obtains Pascal’s triangle modulo $2$, that is, the Sierpinski triangle, a fractal figure. The program automates.py checks it on 32 lines.

★★★Exercise 7 — Deciding whether a configuration dies out

Show that there is no algorithm which, given a one-dimensional cellular automaton with a “blank” state $b$ (with $f(b,b,b)=b$) and a finite configuration, decides whether the configuration eventually becomes entirely blank. One may modify the construction of the simulation theorem.

Solution

Start from the automaton that simulates a machine $Z$ from the blank tape, and modify it in three ways. (1) The cells the head has already visited are marked (the states are doubled: $s$ and $\bar s$); the marked region is an interval, since the head moves one cell at a time, and it contains all the non-blank cells. The “blank” of the automaton is the unmarked blank $b$. (2) A cell $(q_{\text{halt}},s)$ becomes a state $\varepsilon$, which emits two erasing signals $\varepsilon_L$ and $\varepsilon_R$ into its two neighbours if they are marked, then becomes $b$. (3) A signal $\varepsilon_R$ becomes $b$ at the next step and passes to its right neighbour if that neighbour is marked; likewise for $\varepsilon_L$ to the left. The signals sweep the marked interval leaving blank behind them and vanish at its edges. As long as $Z$ has not halted, the configuration contains the head, so is not blank; if $Z$ halts, everything becomes blank in finitely many steps. The configuration therefore dies out if and only if $Z$ halts on the blank tape, which is undecidable. Result quoted for information: the stronger question “does every configuration eventually become blank?” (nilpotency) is also undecidable (Kari, 1992), but its proof is much harder, since all configurations must be controlled, including those that code no computation.
