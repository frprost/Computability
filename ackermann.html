The Ackermann function

A total function, computable by a program a few lines long, which grows too fast to be primitive recursive: the proof that “for” loops are not enough.

A function that a program of a few lines computes, but which grows so fast that no combination of “repeat $n$ times” loops can reach it. It is the proof that such loops are not enough to compute everything.

PrerequisitesPrimitive recursive functions

In the 1920s, people wondered whether all computable functions could be written with loops whose number of rounds is known in advance (the primitive recursive functions). Wilhelm Ackermann, a student of Hilbert, answered no in 1928 with a function that is very simple to define, but grows at an unimaginable speed.

The idea is to build a ladder of operations: addition repeats “plus one”, multiplication repeats addition, exponentiation repeats multiplication, then exponentiation is repeated, and so on. The Ackermann function climbs all the rungs of this ladder at once.

Definition

The function takes two numbers, $m$ and $n$. The first one says which rung of the ladder (0: add 1, 1: add, 2: multiply…), the second the number to which the operation is applied.

Definition
Ackermann function (Péter’s version)
$$A(0,n)=n+1,\qquad A(m+1,0)=A(m,1),\qquad A(m+1,n+1)=A\big(m,\,A(m+1,n)\big).$$

In plain words. The Ackermann function takes two numbers and returns one. It is defined by three short rules, which say how to compute each value from “smaller” values. Each row of its table of values repeats the previous row.

Wilhelm Ackermann, a student of the great mathematician David Hilbert, invented it in 1928 to answer a precise question: can all the functions that we know how to compute, and that always give an answer, be written with “repeat n times” loops, where the number of rounds is known before starting? His function shows that they cannot. The simpler version presented here is due to the Hungarian mathematician Rózsa Péter (1935).

The recursion is double: it is on the pair $(m,n)$ ordered lexicographically, and the inner call $A(m+1,n)$ supplies the second argument of the outer call, so that the number of calls cannot be bounded in advance.

Proposition
The Ackermann function is well defined and computable

The equations define a unique total function $A:\N^2\to\N$, and this function is computable.

In plain words. These three rules do define a function: for each pair of numbers, they lead to a single answer. A program always computes it in finite time, even if that time can be astronomical.

The reason is that each rule brings the computation back to smaller cases, either because the first number decreases, or because the first stays the same and the second decreases. One cannot go down like this forever, just as one cannot go down forever a staircase that has a ground floor.

One shows by induction on $m$ that, for every $m$, there is a unique function $A_m:\N\to\N$ satisfying the equations of row $m$: $A_0(n)=n+1$; and if $A_m$ is defined, $A_{m+1}$ is defined by (simple) recursion on $n$: $A_{m+1}(0)=A_m(1)$, $A_{m+1}(n+1)=A_m(A_{m+1}(n))$. This is a well-founded recursion on the lexicographic order of $\N^2$: each call is on a strictly smaller pair ($(m,1)<(m+1,0)$, $(m+1,n)<(m+1,n+1)$ and $(m,\cdot)<(m+1,n+1)$), and this order has no infinite descending sequence. Computability follows from Church’s thesis (the program below), or from an explicit definition by minimization: one searches for the least code of a finite “computation tree” consistent with the equations.

An iterative program, with an explicit stack:

ackermann(m, n) :
    stack := [m]
    while stack not empty :
        m := pop(stack)
        if m = 0 :             n := n + 1
        else if n = 0 :        push(stack, m - 1) ; n := 1
        else :                 push(stack, m - 1) ; push(stack, m) ; n := n - 1
    return n

In the λ-calculus, thanks to Church numerals (which are iterators), the function fits on one line: $\mathsf{ACK}=\lambda m.\,m\,(\lambda f.\lambda n.\,n\,f\,(f\,\mathbf 1))\,\mathsf S$. Indeed $A_{m+1}(n)=A_m^{\,n+1}(1)$: iterate $A_m$. The λ-calculus, which allows higher-order iteration (iterating a function that is itself an iteration), thus naturally goes beyond primitive recursion.

Definition
Ackermann’s original three-argument function (1928)

Ch. Boitet’s lecture notes present the function $\alpha:\N^3\to\N$ defined by

$$\alpha(0,x,y)=x+y,\qquad \alpha(1,0,y)=0,\qquad \alpha(z+2,0,y)=1,\qquad \alpha(z+1,x+1,y)=\alpha\big(z,\ \alpha(z+1,x,y),\ y\big).$$

Then $\alpha(1,x,y)=x\,y$, $\alpha(2,x,y)=y^x$, and $\alpha(3,x,y)=y^{y^{\cdot^{\cdot^{y}}}}$ (a tower of $x$ exponents, equal to $1$ for $x=0$).

In plain words. The function Ackermann proposed in 1928 took three numbers as input. The first one chooses the operation: 0 for addition, 1 for multiplication, 2 for exponentiation, and so on.

Multiplication is repeated addition (3 × 4 = 4 + 4 + 4), exponentiation is repeated multiplication (43 = 4 × 4 × 4). Ackermann continues the ladder forever: the next operation repeats exponentiation, which gives towers of exponents, and so on. His function climbs this whole ladder.

By induction on $x$, for fixed $z$: $\alpha(1,x+1,y)=\alpha(0,\alpha(1,x,y),y)=\alpha(1,x,y)+y$, whence $\alpha(1,x,y)=xy$; $\alpha(2,x+1,y)=\alpha(1,\alpha(2,x,y),y)=\alpha(2,x,y)\cdot y$, whence $\alpha(2,x,y)=y^x$; $\alpha(3,x+1,y)=y^{\alpha(3,x,y)}$. Examples: $\alpha(3,2,3)=3^3=27$ and $$\alpha(4,3,2)=\alpha(3,\alpha(4,2,2),2)=\alpha(3,4,2)=2^{2^{2^2}}=65536,$$ since $\alpha(4,1,2)=\alpha(3,1,2)=2$ and $\alpha(4,2,2)=\alpha(3,2,2)=4$. Well-definedness is proved as for $A$, by induction on $(z,x)$ in lexicographic order. That $\alpha$ is not primitive recursive is proved below, by reducing $\alpha$ to $A$ through an exact identity.

Ackermann (“Zum Hilbertschen Aufbau der reellen Zahlen”, Mathematische Annalen 99, 1928) wrote $\varphi(a,b,n)$, with the operation in last position, and set $\varphi(a,0,1)=0$, $\varphi(a,0,2)=1$ and $\varphi(a,0,n)=a$ for $n\ge3$. The version in the lecture notes sets $\alpha(z+2,0,y)=1$ for all $z$, which changes the values from $z=3$ on (the number of storeys of the tower) but none of the growth properties.

Link with Péter’s version. For Péter’s function $f(0,y)=y+1$, $f(x+1,0)=f(x,1)$, $f(x+1,y+1)=f(x,f(x+1,y))$, one finds $f(1,y)=y+2$, $f(2,y)=2y+3$, $f(3,y)=2^{y+3}-3$: this is the function $A$ of this chapter, and these are the rows of the table below.

The values above were checked by program (memoized recursion for $z\le4$ and closed forms for $z\le2$): $\alpha(1,3,5)=15$, $\alpha(2,3,5)=125$, $\alpha(3,2,3)=27$, $\alpha(4,3,2)=65536$.

Proposition
Recursiveness of Ackermann via an encoded stack

The function $A$ is recursive (and total): it is obtained from primitive recursive functions by a single minimization.

Encode the state of the iterative program above, the stack $[m_1,\dots,m_k]$ and the current value $n$, by a single integer $c=\langle\mathrm{gn}(m_1,\dots,m_k),n\rangle$, where $\mathrm{gn}$ is the coding of sequences by prime powers. One step of the program, $c\mapsto\mathrm{Step}(c)$, is primitive recursive: it reads the top of the stack, tests whether it is zero and whether $n$ is zero, and rewrites the code (length, top, truncation and appending are primitive recursive). By primitive recursion, $E(t,c)=\mathrm{Step}^t(c)$ is too. Then $$A(m,n)=\pi_2\Big(E\big(\mu t\,[\,\mathrm{length}(\pi_1(E(t,c_0)))=0\,],\ c_0\big)\Big),\qquad c_0=\langle\mathrm{gn}(m),n\rangle.$$ Minimization is the only non-primitive operation; it terminates because the stack empties (well-definedness). It cannot be replaced by a bounded minimization: the number of steps is bounded by no primitive recursive function of $(m,n)$, otherwise $A$ would be primitive recursive.

In plain words. The Ackermann function can be computed by keeping a stack of pending computations, like a pile of files on a desk. This computation is written with a single “while” loop, whose number of rounds is not known in advance.

This is exactly what a computer does when it runs a program that calls itself: it puts the unfinished computations on a stack and takes them back in reverse order. The stack can grow without any predictable limit. This is where “repeat n times” loops fail: we do not know how many rounds to plan for.

Growth

The first rows are modest; the fourth produces towers of powers of 2. $A(4,2)$ already has 19,729 digits, and $A(4,3)$ could not be written down even if every atom in the universe carried a digit.

Proposition
First rows of the Ackermann function
$$A(0,n)=n+1,\quad A(1,n)=n+2,\quad A(2,n)=2n+3,\quad A(3,n)=2^{n+3}-3,\quad A(4,n)=\underbrace{2^{2^{\cdot^{\cdot^{2}}}}}_{n+3}-3.$$

In plain words. The first row adds 1, the second adds 2, the third roughly doubles, the fourth raises 2 to a power, the fifth builds towers of powers of 2.

The growth is dizzying. The value for 4 and 2 is a number with 19,729 digits. The value for 4 and 3 has more digits than there are atoms in the observable universe. Yet the program that computes it fits in five lines, and it always ends up halting, in principle.

By induction on $n$, row by row. For $m=1$: $A(1,0)=A(0,1)=2$ and $A(1,n+1)=A(0,A(1,n))=A(1,n)+1$, so $A(1,n)=n+2$. For $m=2$: $A(2,0)=A(1,1)=3$ and $A(2,n+1)=A(1,A(2,n))=A(2,n)+2$, so $A(2,n)=2n+3$. For $m=3$: $A(3,0)=A(2,1)=5=2^3-3$ and $A(3,n+1)=2A(3,n)+3$; if $A(3,n)=2^{n+3}-3$, then $A(3,n+1)=2^{n+4}-6+3=2^{n+4}-3$. For $m=4$: $A(4,n+1)=2^{A(4,n)+3}-3$, whence the tower.

Ackermann is not primitive recursive

Every function written with “repeat $n$ times” loops is overtaken by a row of the Ackermann function. Now the Ackermann function runs through all the rows: so it overtakes each of these functions, and is not one of them.

Theorem
Every primitive recursive function is dominated by a row of Ackermann

For every primitive recursive function $f:\N^k\to\N$, there is $m$ such that, for all $\vec x$, $f(\vec x)<A(m,\max\vec x)$ (with $\max\vec x=0$ if $k=0$).

In plain words. Every function that can be written with “repeat n times” loops is eventually beaten by a row of the Ackermann function.

A loop inside a loop inside a loop…: the growth rate of such a program is limited by the number of nested loops. Each row of Ackermann’s table corresponds to one more level of nesting. A given program has a fixed number of nestings, and a row far enough down overtakes it.

Lemmas. For all $m,n$:

  1. $A(m,n)>n$;
  2. $A(m,n+1)>A(m,n)$ (increasing in $n$);
  3. $A(m+1,n)\ge A(m,n+1)$, and hence $A(m+1,n)>A(m,n)$ (increasing in $m$);
  4. $A(m_1,A(m_2,n))<A(m_1+m_2+2,n)$;
  5. $A(m,n)\ge m+n+1$.

For (1), induction on $m$, then on $n$: $A(0,n)=n+1>n$; $A(m+1,0)=A(m,1)>1>0$; and $A(m+1,n+1)=A(m,A(m+1,n))>A(m+1,n)>n$, so $A(m+1,n+1)\ge n+2$. For (2): $A(0,n+1)=n+2>n+1$, and $A(m+1,n+1)=A(m,A(m+1,n))>A(m+1,n)$ by (1). For (3), induction on $n$: for $n=0$ it is the equality $A(m+1,0)=A(m,1)$; if $A(m+1,n)\ge A(m,n+1)$, then $A(m+1,n)\ge A(m,n+1)>n+1$ by (1), so $A(m+1,n)\ge n+2$, and by (2), $A(m+1,n+1)=A(m,A(m+1,n))\ge A(m,n+2)$. The second part follows from (2): $A(m,n+1)>A(m,n)$. In particular $A$ is increasing in each of its arguments. For (5), induction on $m$: $A(0,n)=n+1$, and $A(m+1,n)\ge A(m,n+1)\ge m+n+2$ by (3).

For (4), with $m=\max(m_1,m_2)$ and using the monotonicity properties (2) and (3): $A(m_1,A(m_2,n))\le A(m,A(m,n))<A(m,A(m+1,n))=A(m+1,n+1)\le A(m+2,n)\le A(m_1+m_2+2,n)$.

Induction on the construction of $f$; write $|\vec x|=\max\vec x$.

  • Constants: $c<A(c,0)\le A(c,|\vec x|)$ by (5) and (2). Successor: $x+1<x+2=A(1,x)$. Projections: $x_i\le|\vec x|<A(0,|\vec x|)$.
  • Substitution $f=\sigma[g,h_1,\dots,h_k]$ with $h_i(\vec x)<A(r,|\vec x|)$ (take $r$ the largest of the $r_i$) and $g(\vec y)<A(s,|\vec y|)$: $f(\vec x)<A\big(s,\max_i h_i(\vec x)\big)<A(s,A(r,|\vec x|))<A(s+r+2,|\vec x|)$.
  • Recursion $f=\rho[g,h]$ with $g<A(r,\cdot)$, $h<A(s,\cdot)$. Set $q=\max(r,s)+1$. We show by induction on $y$ that $f(y,\vec x)<A(q,y+|\vec x|)$. For $y=0$: $f(0,\vec x)=g(\vec x)<A(r,|\vec x|)\le A(q,|\vec x|)$. Next, $y$, $|\vec x|$ and $f(y,\vec x)$ are all $<A(q,y+|\vec x|)$, so $$f(y+1,\vec x)=h(y,f(y,\vec x),\vec x)<A\big(s,A(q,y+|\vec x|)\big)\le A\big(q-1,A(q,y+|\vec x|)\big)=A(q,y+1+|\vec x|).$$ Finally $y+|\vec x|\le 2\max(y,|\vec x|)<A(2,\max(y,|\vec x|))$, whence $f(y,\vec x)<A(q,A(2,\cdot))<A(q+4,\max(y,|\vec x|))$.
Corollary
The Ackermann function is not primitive recursive

$A$ is computable and total, but not primitive recursive. More precisely, the diagonal function $d(n)=A(n,n)$ is not primitive recursive.

If $A$ were primitive recursive, so would be $d=\sigma[A,A^{(1)}_1,A^{(1)}_1]$; by the theorem, there would be $m$ such that $d(n)<A(m,n)$ for all $n$. For $n=m$: $A(m,m)<A(m,m)$, a contradiction.

In plain words. The Ackermann function can be computed and always gives an answer, but it cannot be written with “repeat n times” loops alone.

This is Cantor’s diagonal once again. Each program with bounded loops is beaten by a row. By taking, for each number n, the value of row n at n, we beat all the rows at once, hence all these programs. We check concretely what the argument of the motivations announced: a language in which all loops are limited in advance does not compute everything, even among the functions that always give an answer.

Theorem
The function α of the lecture notes is not primitive recursive

(1) For every $z\ge1$, $\alpha(z,1,2)=2$; for every $z$, $\alpha(z,2,2)=4$ and $\alpha(z+1,3,2)=\alpha(z,4,2)$.

(2) For all $z,x$: $\ \alpha(z,\,x+3,\,2)=A(z+1,\,x)+3$.

(3) The function $\alpha$ is not primitive recursive; more precisely $x\mapsto\alpha(x,x+3,2)$ is not.

In plain words. Ackermann’s original function, with three numbers, cannot be computed with “repeat n times” loops either, for the same reason.

The two versions are in fact the same ladder of operations (addition, multiplication, exponentiation, tower…), seen in two ways. So it is not an accident of the definition: it is the repetition of operations itself that grows too fast for loops fixed in advance.

(1) For $z\ge1$, by induction on $z$: $\alpha(1,1,2)=\alpha(0,\alpha(1,0,2),2)=0+2=2$, and $\alpha(z+1,1,2)=\alpha(z,\alpha(z+1,0,2),2)=\alpha(z,1,2)=2$ since $\alpha(z+1,0,2)=1$ for $z\ge1$. Next $\alpha(0,2,2)=4$ and, for every $z$, $\alpha(z+1,2,2)=\alpha(z,\alpha(z+1,1,2),2)=\alpha(z,2,2)$, whence $\alpha(z,2,2)=4$ by induction. Finally $\alpha(z+1,3,2)=\alpha(z,\alpha(z+1,2,2),2)=\alpha(z,4,2)$. (This is the first question of the exercise in the lecture notes, here for every $z$.)

(2) Induction on $z$, and for each $z$ induction on $x$. For $z=0$: $\alpha(0,x+3,2)=x+5=A(1,x)+3$, since $A(1,x)=x+2$ (first rows). Assume the identity holds for $z$ and every $x$. For $z+1$ and $x=0$: $$A(z+2,0)+3=A(z+1,1)+3=\alpha(z,4,2)=\alpha(z+1,3,2),$$ by the hypothesis (with $x=1$) and then by (1). If the identity holds for $z+1$ and $x$, then $$A(z+2,x+1)+3=A\big(z+1,A(z+2,x)\big)+3=\alpha\big(z,\,A(z+2,x)+3,\,2\big)=\alpha\big(z,\,\alpha(z+1,x+3,2),\,2\big)=\alpha(z+1,x+4,2),$$ applying the hypothesis on $z$ at the point $A(z+2,x)$, then the hypothesis on $x$, then the definition of $\alpha$.

(3) If $\alpha$ were primitive recursive, so would be $g(x)=\alpha(x,x+3,2)\monus3$ (substitution), and $g(x)=A(x+1,x)$ by (2). By the domination theorem, there would be $m$ such that $g(x)<A(m,x)$ for all $x$. For $x=m$: $A(m+1,m)<A(m,m)$, which contradicts lemma (3) of that theorem, $A(m+1,m)>A(m,m)$.

The lecture notes suggest another route, as an exercise: compare $\alpha$ with the simplified function $f$ (which is our $A$) through an inequality $f(z+1,x)+3\le\alpha(z,x+3,2)$; identity (2) shows that this inequality is in fact an equality.

Identity (2) was checked by program (memoized recursion on the definitions of $\alpha$ and $A$) for $z\le2$, $x\le5$, and for $z=3$, $x\in\{0,1\}$: for example $\alpha(2,8,2)=256=A(3,5)+3=253+3$, $\alpha(3,3,2)=16=A(4,0)+3$ and $\alpha(3,4,2)=2^{16}=65536=A(4,1)+3$. The equalities (1) were checked for $z\le4$.

Exercises

Levels: ★ direct application of the course, ★★ standard exercise, ★★★ going further. Solutions are hidden: click “Solution” to show them.

★Exercise 1 — The first two rows

Show that $A(1,n)=n+2$ and $A(2,n)=2n+3$, then compute $A(2,3)$ and $A(3,1)$.

Solution

By induction on $n$. $A(1,0)=A(0,1)=2$ and $A(1,n+1)=A(0,A(1,n))=A(1,n)+1$, whence $A(1,n)=n+2$. Then $A(2,0)=A(1,1)=3$ and $A(2,n+1)=A(1,A(2,n))=A(2,n)+2$, whence $A(2,n)=2n+3$. Thus $A(2,3)=9$, and $A(3,1)=A(2,A(3,0))=A(2,A(2,1))=A(2,5)=13$. One recovers the table of the first rows: each row iterates the previous one.

★★Exercise 2 — Monotonicity in each argument

Show that, for all $m,n$: $A(m,n)>n$ and $A(m,n+1)>A(m,n)$.

Solution

We argue by induction on $m$, and for fixed $m$ by induction on $n$.

$A(m,n)>n$. For $m=0$, $A(0,n)=n+1$. Assume it for $m$ (and every $n$). Then $A(m+1,0)=A(m,1)>1>0$, and if $A(m+1,n)>n$, that is $A(m+1,n)\ge n+1$, then $A(m+1,n+1)=A(m,A(m+1,n))>A(m+1,n)\ge n+1$.

Monotonicity. For $m=0$, it is clear. For $m+1$: $A(m+1,n+1)=A(m,A(m+1,n))>A(m+1,n)$, by the first point applied to $m$. These two inequalities are the basic lemmas of the domination proof.

★★★Exercise 3 — A primitive recursive graph

Show that the graph $\{(m,n,v):A(m,n)=v\}$ is primitive recursive. Deduce that a total function whose graph is primitive recursive need not be primitive recursive.

Solution

Call a finite set $S$ of triples justified if each $(i,j,w)\in S$ agrees with the equations by means of triples of $S$: $i=0$ and $w=j+1$; or $i>0$, $j=0$ and $(i-1,1,w)\in S$; or $i,j>0$ and there is $u$ with $(i,j-1,u)\in S$ and $(i-1,u,w)\in S$.

(1) If $S$ is justified, all its triples are correct ($w=A(i,j)$): by induction on $(i,j)$ in lexicographic order, each triple relies on triples of lower rank. (2) If $A(m,n)=v$, the set of calls made by the recursive computation of $A(m,n)$, together with their results, is justified. All its triples $(i,j,w)$ satisfy $i\le m$, $w\le v$ and $j<w$: the first coordinate only decreases, and by the previous exercise the results of inner calls are smaller than those of the calls containing them ($A(i,j-1)<A(i-1,A(i,j-1))=A(i,j)$), and $j<A(i,j)$.

Hence $A(m,n)=v$ if and only if there is a justified subset of $[0,m]\times[0,v]^2$ containing $(m,n,v)$. Such a subset is encoded by an integer less than $2^{(m+1)(v+1)^2}$, and “$S$ is justified” is checked by bounded quantifiers: the graph is primitive recursive. Yet $A$ is not primitive recursive (corollary). We have $A(m,n)=\mu v\,[G(m,n,v)]$ with $G$ primitive recursive: a single minimization, always defined, is enough to leave $\RP$.
