Every programmer has known a program that “runs” forever: we wait, not knowing whether it will finish or is stuck in a loop. Could we not write a tool that examines a program and says in advance: “this one will halt”, or “this one will run forever”?

In 1936, Turing proved that this is impossible, not for lack of ingenuity or computing power, but by a logical impossibility, as final as the impossibility of building a round square. This chapter explains why, then shows that this impossibility spreads to almost all the questions we would like to ask about the behaviour of programs.

The halting problem

Turing’s proof resembles the liar paradox (“this sentence is false”). Suppose that a magic program, let us call it “Oracle”, could tell of every program whether it halts. We then write a program “Contrarian” that asks Oracle about itself and does the opposite of the prediction: if Oracle announces “Contrarian halts”, Contrarian runs forever; if Oracle announces “it runs forever”, Contrarian halts at once. Oracle is bound to be wrong about Contrarian. So Oracle does not exist.

The first argument for non-computability was a size argument: there are more functions than programs. It is correct but non-constructive. Which functions, concretely, are not computable? The most natural candidate is linked to partiality: the only way for a computation not to answer is not to halt. Can one predict, from outside, whether a computation will halt?

The set $K=\{e\in\N:\varphi_e(e)\conv\}$ is not decidable. Consequently the set $H=\{\langle e,x\rangle:\varphi_e(x)\conv\}$ (often written $K_0$) is not decidable either: no program takes as input a program $e$ and a datum $x$, always halts, and answers correctly whether $e$ halts on $x$.

In plain words. There is no program that, given any program and any input, always says correctly whether this program will halt on this input.

There is not, and there will never be, a tool that examines any program and predicts for certain whether it will finish or loop forever. It is not a question of technology: a computer a thousand times faster would change nothing. Real tools detect many infinite loops, but each one is wrong or silent about some programs.

The proof works like the liar paradox. If such a seer existed, we would write a program that asks it about itself and does the opposite of what it announces. The seer would be wrong about that program: so it cannot exist.

Suppose $\chi_K$ is computable. The function

$$p(e)\simeq\begin{cases}0&\text{if }\chi_K(e)=0,\\ \ind&\text{if }\chi_K(e)=1\end{cases}$$

is then computable (compute $\chi_K(e)$; if it is 0, return 0, otherwise enter an infinite loop). Let $q$ be an index of $p$. If $\varphi_q(q)\conv$, then by definition $p(q)\ind$, that is $\varphi_q(q)\ind$; and if $\varphi_q(q)\ind$, then $p(q)=0$, so $\varphi_q(q)\conv$. Both cases are contradictory: $\chi_K$ is not computable.

For $H$: if $\chi_H$ were computable, so would be $\chi_K(e)=\chi_H(\langle e,e\rangle)$.

The paradox, written as a program that uses its own text (which the recursion theorem allows):

contrarian() :
    me := text of this program            // recursion theorem
    if halts(me, empty_input) :
        loop forever
    else :
        halt

Whatever function halts is proposed, provided it always terminates, it is wrong about contrarian. The argument even gives a counterexample computable from the text of halts: the impossibility is constructive.

The simulators of this manual stop after a fixed maximal number of steps: they do not decide halting, they observe it, when it happens before the limit. This is all a program can do in general.

The file halting.py of the downloadable programs makes the proof concrete. A candidate “decider” is a Python function decide(source, x) that claims to tell whether the program with text source halts on input x. The function paradox builds the diagonal program $D$: thanks to the fixed point, $D$ has its own text in the variable SELF, asks the decider what it will do on itself, and does the opposite.

Four candidates are put to the test, from the most naive to the most reasonable (simulate the program for 1,000 lines and answer “it halts” if it has finished). Each one is wrong about its diagonal program:

$ python3 halting.py
Candidate "always answers yes"
   it claims that D halts on its own text
   in fact, D: no halt within the budget
   the candidate is wrong: yes
...
Candidate "simulates 1000 lines and concludes"
   it claims that D does not halt on its own text
   in fact, D: halts
   the candidate is wrong: yes

An infinite run obviously cannot be watched to its end: the program runs $D$ with a budget of lines. But for the first candidate the text of $D$ shows the loop while True: pass directly, and it is reached since the decider answers yes. The last candidate illustrates the real lesson: simulating “long enough” is never enough, because the diagonal program itself simulates the decider and halts just after it.

Reductions

Once a problem is known to be impossible, other impossibilities follow from it by a simple argument: if knowing how to solve problem B made it possible to solve the halting problem, then B is impossible too. We say that halting has been “reduced” to B.

The halting problem seems very special. It is not: many problems reduce to it, by the technique of reduction. To show that a problem $B$ is undecidable, one shows that if $B$ were decidable, halting would be too.

$A\le_m B$ if there is a total computable function $f$ such that, for every $x$, $x\in A\iff f(x)\in B$. If $A\le_m B$ and $B$ is decidable, then so is $A$: $\chi_A=\chi_B\circ f$. Hence if $A$ is undecidable and $A\le_m B$, $B$ is undecidable.

In plain words. Reducing a problem A to a problem B means finding an automatic way of turning each question of A into a question of B that has the same answer.

If we knew how to solve B, we would therefore know how to solve A. Contrapositive: if A is impossible, so is B. This is how the impossibility of halting spreads, step by step, to hundreds of other problems.

The following problems are undecidable:

  1. (Use of a variable) Given a program $P$ without input and a variable $v$, does the execution of $P$ use $v$?
  2. (Dead code) Will a given instruction of a program be executed?
  3. (Value at a point) Given a program $P$, is $P(12)=7$?
  4. (Totality) Does the program $P$ halt on all its inputs?
  5. (Equivalence) Do two programs compute the same function?

In plain words. One cannot decide automatically whether a program always halts, whether it always returns the same value, whether it computes the same thing as another program, or whether it reaches a certain line.

These are the questions that development tools ask every day: detect useless code, check that a change has broken nothing, make sure that a program never crashes. These tools exist and render immense services, but none can be right in all cases: they must sometimes answer “I don’t know”, or err on the side of caution.

(1) From $P$ (without input), choose a variable $v$ absent from $P$ and form $P'=P;\ v:=v+1$. Then $P'$ uses $v$ if and only if $P$ halts. The map $P\mapsto(P',v)$ is computable: it is a reduction of halting on empty input (undecidable, by an immediate reduction from $H$) to problem (1). (2) is similar: the instruction $v:=v+1$ is reached if and only if $P$ halts.

(3) From a program $Q$ and a datum $w$, form the program $P_{Q,w}$ which, on every input $x$, runs $Q$ on $w$ and then returns 7. Then $P_{Q,w}(12)=7$ if and only if $Q$ halts on $w$, and $(Q,w)\mapsto P_{Q,w}$ is computable (s-m-n). (4) With the same $P_{Q,w}$: it is total if and only if $Q$ halts on $w$. (5) If equivalence were decidable, so would totality be (compare $P_{Q,w}$ with the constant program 7).

The program of reduction (3), in pseudo-code. It is obtained from $Q$ and $w$ by mere text manipulation, without running $Q$:

P_{Q,w}(x) :
    run Q on w              // may never finish
    return 7

At the level of Turing machines, this is the construction of the s-m-n theorem: erase the input, write $\overline w$, run $Q$ (states renamed), then erase the tape and write 7 strokes.

The following index sets are undecidable:

  1. $\mathrm{Cst}=\{x:\varphi_x$ is a total constant function$\}$;
  2. $B=\{x:\varphi_x(4)=12\}$, and more generally $\{x:\varphi_x(a)=b\}$ for all $a,b$;
  3. $C=\{x:\varphi_x(23)\ind\}$;
  4. $\{\langle x,y,z\rangle:\varphi_x(y)=z\}$: even when the expected value is specified, halting remains undecidable;
  5. $\{\langle x,y\rangle:\varphi_x=\varphi_y\}$ (program equivalence);
  6. $\{x:\mathrm{Im}\,\varphi_x\text{ is infinite}\}$ and $\{x:y_0\in\mathrm{Im}\,\varphi_x\}$ for every fixed $y_0$;
  7. $\mathrm{Tot}=\{x:\varphi_x\text{ is total}\}$.

On the other hand, for a fixed index $x_0$, the set $\mathrm{Im}\,\varphi_{x_0}$ may or may not be decidable depending on $x_0$.

In plain words. Each of these impossibilities is proved by showing that a tool that answered it would make it possible to solve the halting problem.

The scenario is always the same: we build a program that starts by simulating a computation of which we do not know whether it halts, and that does “the interesting thing” only afterwards. Answering the question about this program means knowing whether the initial computation halts.

Let $g(x,y)\simeq 12$ if $\varphi_x(x)\conv$, and $g(x,y)\ind$ otherwise. The function $g$ is computable (simulate $\varphi_x(x)$; if the simulation halts, return 12). Let $n$ be an index of $g$; by the s-m-n theorem, $h(x)=s^1_1(n,x)$ is total computable and $\varphi_{h(x)}(y)=g(x,y)$. Thus:

  • if $x\in K$, $\varphi_{h(x)}$ is the constant 12; if $x\notin K$, $\varphi_{h(x)}$ is nowhere defined. Hence $x\in K\iff h(x)\in\mathrm{Cst}\iff h(x)\in B\iff \langle h(x),4,12\rangle\in\{\langle x,y,z\rangle:\varphi_x(y)=z\}\iff h(x)\in\mathrm{Tot}$: $K$ reduces to (1), (2), (4) and (7);
  • $x\notin K\iff h(x)\in C$: it is the complement $\overline K$ that reduces to $C$, which suffices, since $\overline K$ is undecidable as soon as $K$ is;
  • if $y_0$ is an index of the everywhere-defined zero function, $x\in K\iff\langle h'(x),y_0\rangle$ is in the set (5), where $h'$ is built in the same way with the value 0;
  • for (6), take $\varphi_{h_2(x)}(y)\simeq y$ if $x\in K$, $\ind$ otherwise: the range is $\N$ (infinite, contains $y_0$) or empty.

For $\mathrm{Tot}$, a direct proof by diagonalization can also be given: if $f$ computed the characteristic function of $\mathrm{Tot}$, the function $g(0)=\mu y[f(y)=1]$, $g(x+1)=\mu y[f(y)=1\wedge y>g(x)]$ would enumerate the indices of total functions, and $d(x)=\varphi_{g(x)}(x)+1$ would be total computable without being any of the $\varphi_{g(x)}$ (it differs from $\varphi_{g(x_0)}$ at $x_0$). In fact $\mathrm{Tot}$ is not even semi-decidable, nor co-semi-decidable: it is a $\Pi_2$-complete set (Arithmetical hierarchy).

Rice’s theorem

Rice’s theorem generalizes all this at a stroke: no interesting question about what a program does can be settled automatically in all cases.

Let $\mathcal F$ be a set of computable functions of one variable which is non-trivial ($\mathcal F\neq\emptyset$ and $\mathcal F$ does not contain all computable functions). Then the set $\{e:\varphi_e\in\mathcal F\}$ of indices of the functions in $\mathcal F$ is not decidable.

In plain words. Every property of the behaviour of a program (what it computes, and not how it is written) is impossible to decide automatically, as soon as it is neither always true nor always false.

“Does this program compute the average correctly?”, “does this program send out personal data?”, “is this software a virus?”: none of these questions can be settled by a program that would always be right. On the other hand, the text of a program can be examined (its length, the words it contains): this is what antivirus software does, and it is why a virus that modifies its text can escape it.

Let $\Theta$ be the nowhere-defined function. Replacing $\mathcal F$ by its complement if necessary (which does not change decidability), we may assume $\Theta\notin\mathcal F$. Since $\mathcal F\ne\emptyset$, choose $\psi\in\mathcal F$. By s-m-n, there is a total recursive $f$ such that

$$\varphi_{f(e)}(x)\simeq\begin{cases}\psi(x)&\text{if }\varphi_e(e)\conv,\\ \ind&\text{otherwise}\end{cases}$$

(compute $\varphi_e(e)$, then, if it halts, $\psi(x)$). Then $\varphi_{f(e)}=\psi\in\mathcal F$ if $e\in K$, and $\varphi_{f(e)}=\Theta\notin\mathcal F$ if $e\notin K$. Hence $K\le_m\{e:\varphi_e\in\mathcal F\}$ via $f$, and the latter set is undecidable.

The reduction, in pseudo-code: given $e$, build (without running it) the program

F_e(x) :
    run program e on input e        // may never finish
    return psi(x)                   // psi : an example having the property

It has the property if and only if $e\in K$. A decider for the property therefore decides $K$.

The theorem speaks only of semantic properties. Syntactic properties are often decidable: “does the program contain a while loop?”, “does it have fewer than 100 lines?”, “is it well typed?” (in many languages). This is why type systems are so useful: they replace an undecidable semantic question by a decidable syntactic one, at the price of rejecting some correct programs.

Links with logic

If we could predict whether programs halt, we would solve at a stroke mathematical riddles open for centuries. This is another way of measuring how hard this problem is.

Goldbach’s conjecture (every even integer $\ge4$ is a sum of two primes) is true if and only if a certain program without input, which searches for a counterexample, does not halt.

In plain words. A tool able to predict whether programs halt would solve Goldbach’s conjecture (“every even number greater than 2 is the sum of two primes”), open since 1742.

It would be enough to write a program that searches for a counterexample, trying all even numbers one by one, and to ask the tool whether this program halts. Many other great questions of mathematics (including the Riemann hypothesis) likewise come down to the halting of a program. Turing’s impossibility therefore also has a mathematical reach.

The program tests successively $x=4,6,8,\dots$ and halts as soon as it finds an $x$ that is not a sum of two primes. Each test is a bounded search (try all $p\le x$). The program halts if and only if the conjecture is false. More generally, every statement of the form $\forall x\,R(x)$ with $R$ decidable (a $\Pi_1$ statement, see Arithmetical hierarchy) is equivalent to the non-halting of a program.

 
x := 4
while true :
    decomposable := false
    for p from 2 to x - 2 :
        if prime(p) and prime(x - p) : decomposable := true
    if not decomposable :
        print x ; halt                  // counterexample found
    x := x + 2

The conjecture has been checked by computer up to $4\times10^{18}$ (Oliveira e Silva, Herzog and Pardi, 2014): this program has not yet found a counterexample, which proves nothing.

Degrees of undecidability

Not all impossible problems are impossible to the same degree. Some are more so than others, and they can be ranked, as one ranks difficulties: this is the theory of degrees of undecidability.

The decidable/undecidable distinction is finer than it seems: some problems are “more undecidable” than others. The halting problem is complete for the semi-decidable problems: every semi-decidable problem reduces to it (see Semi-decidability). But there are strictly harder problems, such as the totality of a program, which even a halting oracle does not decide. The arithmetical hierarchy classifies these degrees according to the logical form of statements.

For $A,B\subseteq\N$, we define, from strongest to weakest:

  • $A\le_1 B$ (one-one) if there is a total computable injective $f$ such that $x\in A\iff f(x)\in B$;
  • $A\le_m B$ (many-one): the same without requiring injectivity (this is the reduction used in this chapter);
  • $A\le_{tt} B$ (truth-table): to decide $x\in A$, compute a finite list of questions $y_1,\dots,y_p$ and a Boolean formula, then evaluate the formula on the answers “$y_j\in B$?”;
  • $A\le_T B$ (Turing): $A$ is decidable by a machine equipped with an oracle for $B$ (oracle machine), which may ask its questions adaptively and in unbounded number.

We have $A\le_1B\Rightarrow A\le_mB\Rightarrow A\le_{tt}B\Rightarrow A\le_TB$, and none of the converses holds in general. For example $\overline K\le_T K$ (invert the oracle’s answer), but $\overline K\not\le_m K$ (otherwise $\overline K$ would be semi-decidable). Two one-one equivalent sets are even recursively isomorphic (Myhill’s theorem), and the level of a problem in the arithmetical hierarchy is measured by these reductions.

In plain words. There are several precise ways of saying “problem A is no harder than problem B”, depending on how we are allowed to use a solution of B to solve A.

We may be allowed only a single question to B, or several, or as many as we like. These variants make it possible to compare finely problems that are all impossible, as one compares climbing difficulties that are all beyond our strength.

There are two semi-decidable sets $A$ and $B$ such that $A\not\le_TB$ and $B\not\le_TA$. In particular, $A$ and $B$ are neither decidable nor $T$-complete: their degree lies strictly between that of $\emptyset$ and that of $K$, which answers Post’s problem negatively.

In plain words. There are two impossible problems, both “half solvable”, such that neither of the two makes it possible to solve the other.

One might have thought that impossible problems are arranged on a single scale. It is not so: there are incomparable difficulties, of a different nature. Relativization. The same construction, in which all machines additionally receive a fixed oracle $C$ (requirements $c_A\ne\varphi^{B\oplus C}_e$ and $c_B\ne\varphi^{A\oplus C}_e$, with $X\oplus C=\{2x:x\in X\}\cup\{2x+1:x\in C\}$, and $A,B$ enumerated with the help of $C$), gives $A,B$ semi-decidable relative to $C$ with $A\not\le_TB\oplus C$ and $B\not\le_TA\oplus C$. For $C=\emptyset^{(n)}$, $A$ is $\Sigma_{n+1}$ (Post’s theorem); it is neither $\Sigma_n$ nor $\Pi_n$, otherwise $A\le_T\emptyset^{(n)}\le_TB\oplus C$; and it is not of the degree of $\emptyset^{(n+1)}$, otherwise $B\oplus C\le_T\emptyset^{(n+1)}\le_TA\le_TA\oplus C$.

Three impossibilities

Three practical consequences: a program that sometimes loops cannot be “repaired” by making it return a default value; unbounded search cannot be done without; the maximal duration of a computation cannot be fixed in advance.

Boitet’s lecture notes end the study of unsolvable problems with three results that close doors one might want to open.

There is a partial computable function $\psi$ such that no total computable function $f$ extends it (that is, satisfies $f(x)=\psi(x)$ whenever $\psi(x)\conv$).

In plain words. Some programs that sometimes loop cannot be “repaired”: no program that always halts gives the same answers as they do where they give any.

One might hope to correct a faulty program by making it return a default value, for example 0, in the cases where it does not halt. This is impossible in general, because one would have to be able to recognize these cases, that is, solve the halting problem.

Let $\psi(x)\simeq\varphi_x(x)+1$. It is computable (universal function). If a total computable $f$ extended it, we would have $f=\varphi_{x_0}$ for some $x_0$; since $f$ is total, $\varphi_{x_0}(x_0)\conv$, so $\psi(x_0)\conv$ and $\varphi_{x_0}(x_0)=f(x_0)=\psi(x_0)=\varphi_{x_0}(x_0)+1$: a contradiction.

In the Kleene normal form $\varphi_e(x)\simeq U(\mu y\,T(e,x,y))$, the output function $U$ cannot be removed: there is a partial computable function $\psi$ that cannot be written $\psi(x)\simeq\mu y\,[f(x,y)=1]$ with $f$ total computable.

In plain words. In general, a small computation after the search cannot be done without: the search alone is not enough to compute everything.

A search gives the first number that fits; it often still has to be transformed to obtain the answer. The result shows that the form “one search, then a simple computation” is the most economical possible.

Let $\psi(x)\simeq x$ if $x\in K$, and $\ind$ otherwise; it is computable. If $\psi(x)\simeq\mu y[f(x,y)=1]$, then for $x\in K$ we have $\psi(x)=x$, so $f(x,x)=1$; for $x\notin K$, $\psi(x)\ind$, so $f(x,y)\ne1$ for all $y$, in particular $f(x,x)\neq1$. Thus $x\in K\iff f(x,x)=1$, and $K$ would be decidable.

There is no total computable function $f(x,y)$ such that, for all $x,y$: if $\varphi_x(y)\conv$, then the computation halts in fewer than $f(x,y)$ steps.

In plain words. One cannot fix, by a computation, a duration beyond which we would be sure that a program will no longer halt.

Computer systems use timeouts: after a certain time, they give up. This theorem says that every timeout computable in advance is sometimes too short: some programs halt just after we have given up. Timeouts are a practical compromise, never a certainty.

The predicate $m(x,y,w)$: “$\varphi_x(y)$ halts in fewer than $w$ steps” is primitive recursive (simulate $w$ steps; this is a consequence of the construction of Kleene’s predicate). If $f$ existed, $\chi(x,y)=m(x,y,f(x,y))$ would be total computable and would equal 1 if and only if $\varphi_x(y)\conv$: it would decide halting.

This is exactly the situation of the simulators of this manual: the “max steps” field is a timeout. The machine of the example Σ(5) halts after 47,176,870 steps; with a timeout of 47 million steps, one would wrongly conclude that it loops.

Exercises

Which of the following sets are decidable? (a) $\{e:e\text{ is even}\}$; (b) $\{e:\varphi_e(3)=5\}$; (c) the set of $e$ such that the machine encoded by $\eta(e)$ has fewer than 10 states; (d) the set of $e$ such that $\varphi_e$ is the zero function; (e) the set of $e$ such that the computation of $\varphi_e(0)$ halts in fewer than 100 steps.

(a), (c) and (e) are decidable; (b) and (d) are not.

  • (a): a parity test. It is not a property of the function $\varphi_e$: two indices of the same function may be one even and one odd. Rice’s theorem does not apply.
  • (c): decode $\eta(e)$ and count the states; this is a property of the text of the program, not of the function computed.
  • (e): run at most 100 steps, which always terminates. The property depends on the program (a slower program computes the same function).
  • (b) and (d) are index sets $\{e:\varphi_e\in\mathcal F\}$ with $\mathcal F$ non-trivial: the functions with value 5 at 3, the zero function alone. Rice’s theorem applies.

The lesson: Rice forbids deciding semantic properties (of the function computed), not syntactic properties nor properties of bounded execution.

Show directly, by a reduction from $K$, that $\{e:\varphi_e(0)\conv\}$ is not decidable.

The function $\psi(e,x)\simeq\varphi_e(e)$ (which ignores $x$) is computable. By s-m-n, there is a primitive recursive $f$ with $\varphi_{f(e)}(x)\simeq\varphi_e(e)$ for all $x$. Then $e\in K\iff\varphi_e(e)\conv\iff\varphi_{f(e)}(0)\conv$. Hence $K\le_m\{e:\varphi_e(0)\conv\}$, which is undecidable since $K$ is (reduction).

Show that $K\le_m\{e:W_e\text{ is infinite}\}$ and $K\le_m\{e:\varphi_e\text{ is total}\}$.

With the same $f$ as in the previous exercise, $W_{f(e)}=\N$ if $e\in K$, and $W_{f(e)}=\emptyset$ otherwise. Hence $e\in K\iff W_{f(e)}$ infinite $\iff\varphi_{f(e)}$ total: the same function realizes both reductions. These sets are in fact strictly harder than $K$ (they are $\Pi_2$-complete).

Show that $\{\langle a,b\rangle:\varphi_a=\varphi_b\}$ is not decidable.

Fix an index $z$ of the zero function. The map $a\mapsto\langle a,z\rangle$ is computable and $\varphi_a=\varphi_z\iff\langle a,z\rangle\in\{\langle a,b\rangle:\varphi_a=\varphi_b\}$. It therefore reduces $\{a:\varphi_a\text{ is the zero function}\}$, undecidable by Rice (exercise 1, (d)), to equivalence. Thus no tool can decide, in general, whether a program optimization preserves its behaviour: compilers only apply transformations whose correctness has been proved once and for all.

Let $\sigma(n)=\max\{\varphi_e(0):e\le n,\ \varphi_e(0)\conv\}$ (with $\max\emptyset=0$). Show that no total computable function $f$ satisfies $f(n)\ge\sigma(n)$ for all $n$. You may use the recursion theorem.

Let $f$ be total computable. The function $\psi(e,x)=f(e)+1$ is computable; by the recursion theorem with parameters, there is $e$ such that $\varphi_e(x)=f(e)+1$ for all $x$. In particular $\varphi_e(0)\conv$ and $e\le e$, so $\sigma(e)\ge\varphi_e(0)=f(e)+1>f(e)$: $f$ does not bound $\sigma$ at the point $e$.

This is a version, for indices, of the busy beaver function. The proof by recursion is remarkably short: program $e$ “knows” its own index, computes the alleged bound, and exceeds it by one.
